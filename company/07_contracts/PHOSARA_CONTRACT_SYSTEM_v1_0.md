# 第1部 契約哲学(Contract Philosophy)

1. **信頼が先、条文は後衛:** 契約は疑いの表明ではなく、信頼を長持ちさせる構造である。もめないための文書ではなく、もめても関係が壊れないための文書として書く
2. **明確な責任:** 「誰が・何を・いつまでに・いくらで・何をもって完了とするか」を一義に定める。曖昧さは弱い側(通常は受託者)に牙をむく
3. **長期の関係:** すべての契約は次段(オファーラダー)への扉を残して終わる。終了条項ですら、再会の余地を閉ざさない書き方をする
4. **双方の保護:** クライアントの保護(検収権・機密・返金規定)とPHOSARAの保護(着手金・範囲統制・収穫条項)を同じ真剣さで書く。一方的な契約は短命である
5. **診断が先(Audit-First):** 契約の順序は営業の順序に従う——監査契約が先、制作契約が後。監査なき制作契約の締結は例外(Type 1)である

# 第2部 公式契約類型(Official Contract Types)

## 2.1 二層構造(基本契約+個別契約)

同一クライアントとの取引は、**取引基本契約(共通条項)を1回**締結し、以後の各案件は**個別契約(注文書・SOW)**で発注する二層構造を標準とする。共通条項の重複締結を排し、案件追加を軽くする(梯子の摩擦を減らす)。

```
取引基本契約(共通条項ライブラリCL-01〜CL-12を収録・NDA内包)
 ├─ 個別契約①: 事業監査(L1)
 ├─ 個別契約②: ウェブサイト制作(L3)
 ├─ 変更合意書(Change Order)…個別契約に紐づく
 └─ 個別契約③: 月額支援(L5) …
```

## 2.2 類型一覧

| # | 類型 | 目的 | 範囲 | 使用時点 | 承認 | 依存 |
|---|---|---|---|---|---|---|

# 第3部 収穫条項(Harvest Clause)— 公式条文

## 3.1 公式条文(全個別契約に必須装備)

> **第◯条(成果物の権利および知見の留保)**
> 1. 本件業務の最終成果物(以下「納品物」)に関する著作権(著作権法第27条・第28条の権利を含む)は、委託者が受託者に対し本契約に定める報酬全額を支払った時点で、本契約に定める利用範囲に従い委託者に移転し、または利用許諾される。支払完了前の権利移転は生じない。
> 2. 前項にかかわらず、次の各号は受託者(PHOSARA)に帰属し、移転の対象に含まれない。
> 　(1) 本件業務の遂行を通じて得られた一般的な知見・手法・ノウハウ
> 　(2) 受託者が従前から保有し、または本件業務と並行して開発した、テンプレート・コンポーネント・フレームワーク・デザインシステム・プロンプト・AIワークフローその他の再利用可能な資産(以下「汎用資産」)
> 　(3) 診断・監査の方法論、評価構造、質問体系およびスコアリング体系
> 3. 納品物に汎用資産が組み込まれる場合、受託者は委託者に対し、当該汎用資産を納品物の利用に必要な範囲で使用する、無償・非独占・期限の定めのない利用権を許諾する。
> 4. 受託者は、第2項の知見および汎用資産を、委託者の機密情報を含まない形に限り、自らの事業(改良・他案件への適用・雛形化を含む)に利用できる。
> 5. 委託者は、受託者が本件を実績として公表すること(名称・概要・成果の紹介)について、別紙「開示階層合意」に定める範囲で許諾する。公表の最終判断は受託者の公開承認手続きに従う。

## 3.2 所有マトリクス

| 資産 | 帰属 | 補足 |
|---|---|---|
| 納品物(最終成果物) | **クライアント**(全額入金後・契約範囲) | サイト・ロゴ・報告書・入稿データ |
| クライアント支給素材・機密・データ | **クライアント** | 受託者は業務目的でのみ使用 |
| 一般的知見・手法・ノウハウ | **PHOSARA** | 収穫の儀の法的基盤 |
| テンプレート・コンポーネント | **PHOSARA** | 組込分は3.1第3項のライセンスで顧客利用可 |
| フレームワーク(LIGHT・監査M1–M11・スコアリング) | **PHOSARA** | 方法論は商品そのものであり不移転 |
| プロンプト・AIワークフロー | **PHOSARA** | 顧客データを含む「実行結果」は顧客機密として扱う |
| Design System(PXD)・Brand Book様式 | **PHOSARA** | クライアント固有のVIガイドラインは納品物としてクライアント |
| PBOS知識・STATE・社内記録 | **PHOSARA** | 開示対象ですらない(第7部) |

## 3.3 具体例(条文の運用)

1. **ウェブサイト:** 完成サイトのデザイン・文章・画像構成=クライアント。実装に使ったグリッドシステム・UIコンポーネント・チェックリスト=PHOSARA(サイトに組み込まれた分は無償ライセンスで使い続けられる)。PHOSARAは同コンポーネントを他業界の案件に再利用できる
2. **事業監査:** 報告書と診断結果=クライアント(社内利用は自由)。11モジュールの構造・質問体系・スコアリング=PHOSARA。クライアントは報告書を第三者のコンサルに渡してよいが、PHOSARAの方法論を複製した診断サービスの提供はできない
3. **AI支援:** 構築したプロンプト・ワークフローの雛形=PHOSARA。クライアントの業務データで調整した設定値と実行結果=クライアント機密。PHOSARAは雛形を匿名化・一般化して他社に展開できるが、クライアントの数値・固有名を含む形では一切使えない

# 第4部 知的財産条項(条項ライブラリ CL-04)

| 論点 | 契約上の標準規定 |
|---|---|
| 著作権 | 3.1の通り(全額入金で移転/許諾)。**著作者人格権は行使しない**特約を置く。移転範囲(複製・翻案・二次利用の可否)を個別契約の別紙で明示し、無限定の「全部移転」を既定にしない |
| 商標 | 「PHOSARA」標章の権利は移転しない。クライアント商標は支給素材として扱い、改変には書面承認を要する |
| ライセンス | 第三者素材(フォント・写真・コード)は受託者がライセンスを取得し、種別と帰属(クライアント名義取得か受託者名義か)を納品書に記載する。ライセンス費は見積に含むか実費精算かを個別契約で選択する |
| 利用権 | 納品物の利用地域・媒体・期間は「事業上合理的な範囲で無制限」を標準とし、制限を設ける場合のみ個別契約に記す |
| ポートフォリオ権 | 3.1第5項+開示階層合意(公開可/匿名可/非公開)を締結時に必ず取得する。**取得漏れの契約を締結してはならない**(Execution OS EX-05の検証4点) |
| 事例(ケーススタディ)権 | 成果数値の公表は事前の書面確認を要する(景表法上の裏付け保持と一体運用) |
| オープンソース | OSSはライセンス条項(表示義務・コピーレフト)を遵守し、使用OSS一覧を納品書に添付する。コピーレフトが納品物全体に伝播する構成を、書面合意なく採らない |
| AI生成資産 | 納品物に含まれるAI生成部分は、人間の監修・選択・編集を経た成果物として第3部の権利処理に従う。AI利用の開示(CL-09)とセットで運用する |

# 第5部 支払条項(条項ライブラリ CL-05)— Pricing Governance Q-9〜Q-12の条文化

| 論点 | 標準規定(数値の正はPricing Governance) |
|---|---|
| 着手金 | L3/L4/スプリント=総額の50%。**入金確認をもって着手日とする**。着手金は中途解約時の最低精算額 |
| マイルストーン | L6は個別契約でマイルストーン分割(着手金は総額の50%を下回らない)。各マイルストーンの完了定義と請求額を別紙に明記 |
| 最終支払 | 残金は検収完了後14日以内。**検収完了が請求の起点**(みなし検収を含む・第6部) |
| 前払い | L1監査・L2・月額・スポットは前払い。入金前の役務提供をしない |
| 遅延 | 期日+7日=書面督促/+14日=作業停止(停止中の納期は停止日数分延長)/+30日=解除権発生+法定利率の遅延損害金。遅延中の新規受注をしない |
| 回収手続き | 督促(配管AP-07定型)→停止通知→内容証明→少額訴訟・支払督促の順。各段の実施判断はH。回収コストが債権額を上回る場合の債権放棄はType 1+決定記録 |
| 解約・返金 | Pricing Q-11の通り(監査=ヒアリング前90%返金/実施後返金なし。構築=出来高精算・着手金は最低精算額。月額=最低期間内は残期間請求)。**PHOSARA都合の解約=未着手分全額返金**(Company OS §10.5と同一規定) |
| 中断(サスペンション) | 委託者都合の中断は最長60日。再開時は残工程の納期を再設定し、90日を超える中断は解約とみなし出来高精算する |
| 終了 | 重大な契約違反(是正催告後14日不履行)・支払遅延30日超・信頼関係の破壊(反社会的勢力条項含む)で解除できる。解除時も第3部(収穫)・第7部(機密)・検収済み部分の支払義務は存続する |

# 第6部 検収条項(条項ライブラリ CL-06)— Company OS 第9部の条文化

| 論点 | 標準規定 |
|---|---|
| 納品 | 納品物・使用素材一覧・OSS一覧・再現可能データ・運用手順を納品書とともに引き渡す |
| 検収期間 | 引き渡しから**10営業日**。委託者は期間内に合格通知または具体的な不合格理由を書面で示す |
| みなし検収 | 期間内に通知がない場合、または委託者が納品物の事業利用を開始した場合、検収完了とみなす |
| 検収基準 | 個別契約の別紙「検収項目」に列挙した項目への適合のみを基準とする(感覚的な「イメージと違う」は改訂手続きで扱い、検収拒絶の理由にならない) |
| 改訂 | 各承認点につき2回まで含む。3回目以降はPricing Q-4の追加費用(変更合意書T-09で処理) |
| 不合格時 | 受託者は合理的期間内に無償で修補する(検収項目への不適合に限る)。修補後に再検収 |
| 完了の定義 | 検収完了+残金入金の両方をもって案件完了とする。完了はSTATEに記録され、収穫の儀(EX-11)がクローズ条件となる——**社内的には、収穫なき完了は存在しない** |
| 品質の内部基準 | 品質スコア8点未満・0点項目ありの納品は社内で禁止(検収に出す前にQA・H点で止める)。これは契約条項ではなく、契約より厳しい社内規律である |

# 第7部 機密保持条項(条項ライブラリ CL-07)

| 論点 | 標準規定 |
|---|---|
| 相互性 | 双務。委託者の機密(経営数値・顧客情報・未公開計画・ヒアリング内容)と受託者の機密(方法論の詳細・価格構成の内訳・PBOS/STATE等の社内知識)を相互に保護する |
| 存続期間 | 契約終了後**3年間**(個別契約で延長可) |
| 例外 | 公知情報・独自開発・法令開示要求(開示前に可能な限り通知) |
| 内部への伝播 | 受託者は、機密に接する従業員・外注先に同等の義務を課す(誓約書・発注書面)。**AIエージェント・AIツールへの機密投入はCompany OS §5.6の3条件(学習遮断・契約上の業務利用許可・監修)を満たす場合に限る**旨を契約に明記する |
| プロンプトと実行結果 | 受託者のプロンプト・ワークフロー=受託者機密。委託者データを含む実行結果=委託者機密。両者を分離して保管する(§3.3例3) |
| PBOS資産 | STATE・WORKFLOW・スコアリング詳細等の社内資産は開示対象外。監査報告書には結論と根拠を載せ、社内機構は載せない |
| 保持と削除 | 契約書類=法定年限(原則7年)。作業データ=終了後1年で削除候補→確認の上削除。**削除要求には法定保存分を除き30日以内対応+削除記録**(Company OS §5.5と同一) |

# 第8部 リスク配分条項(条項ライブラリ CL-08)

| 論点 | 標準規定 |
|---|---|
| 責任の一般原則 | 受託者の損害賠償責任は、故意・重過失を除き、**当該個別契約で現に受領した報酬額を上限**とする。逸失利益・間接損害は賠償範囲に含めない |
| 不可抗力 | 天災・感染症・停電・通信障害・戦争等による履行遅滞は債務不履行としない。30日超継続時は協議の上、出来高精算で解約できる |
| 委託者遅延 | 素材提供・確認・検収の遅延日数分、納期は自動延長する。遅延が累計30日を超えた場合は中断(CL-05)へ移行できる |
| 受託者遅延 | 受託者の責による納期遅延は、遅延前に書面で通知し(悪い知らせはP0)、代替日程と影響を提示する。重大な遅延(30日超)は委託者に解約権(既受領の未着手分は返金) |
| 第三者障害 | ホスティング・外部サービス・印刷会社等の第三者の障害・仕様変更は受託者の債務不履行としない。ただし受託者は回避・軽減に合理的に協力する。**印刷は非提供であり、印刷品質の責任を負わない**(Pricing Q-8の条文化) |
| AIの限界 | AIを活用した制作物の最終責任は受託者(人間の監修を経る)が負う。ただしAIモデル自体の仕様変更・提供終了に起因する将来の再現不能は保証しない。事実情報の正確性は一次資料との突合をもって担保する |
| セキュリティ事故 | 受託者は Company OS §5.7の管理を実施する。事故時は**24時間以内に通知**し、封じ込め・復旧・報告(§6.2)を行う。委託者側環境に起因する事故は委託者の責任とする |
| 紛争解決 | 誠実協議→当事者間の直接対応を最優先(公開の場での応酬をしない)→合意管轄(受託者所在地の地方裁判所)。準拠法は日本法 |
| 反社会的勢力 | 相互の表明保証+該当判明時の無催告解除条項を全契約に置く |

# 第9部 コンプライアンス(条項ライブラリ CL-09)

Company OS §5.9(運用表)を上位の正とし、契約上の実装のみ定める:

1. **書面主義:** 全取引で契約書面(電子契約可・電子は印紙不要)。口頭合意での着手を全類型で禁止
2. **インボイス:** 請求書は適格請求書要件に対応。登録番号を契約書頭書に記載
3. **個人情報:** 個人データの取扱いを伴う個別契約には、利用目的・安全管理・再委託制限・返還削除を定めた個人情報取扱条項を追加する
4. **AI開示:** 「受託者は業務の遂行にAIツールを活用する。生成物は人間の監修を経て納品される」旨の条項を基本契約に標準装備する(Company OS §5.6-2の条文化)
5. **消費者保護:** 本システムはB2B取引を前提とする。消費者(個人)との契約が生じる場合は、消費者契約法・特商法上の要件(不当条項の無効・法定表記)を弁護士確認の上、別雛形を新設する(それまでB2C締結を行わない)
6. **下請法:** PHOSARAが委託側になる外注では、発注書面の交付・給付受領から60日以内の支払・買いたたき禁止を遵守する(外注発注書雛形に組込)
7. **記録保存:** 契約書・注文書・検収記録・請求書は7年保存(`07_clients/`+台帳)

# 第10部 契約統治(Contract Governance)

| 項目 | 規則 |
|---|---|
| 締結権限 | **契約の締結・変更・解除は人間のみ(H領域・永久・Type 1)。** 決定記録(日付・理由・却下代替案)を残す |
| 起案 | Proposer(A-09)が雛形から個別契約を起案。**雛形にない条項・雛形からの逸脱は起案段階でフラグし、H判断+必要に応じ弁護士確認**。Pricing Governance外の金額を契約書に書けない |
| 検証 | 締結前チェック(EX-05の4点): ①収穫条項 ②支払条件 ③スコープと検収項目 ④変更手続き——の全装備をQA(A-10)が機械的に確認する |
| 雛形の改版 | 起案=Proposer/承認=人間(Type 1)。**初版および重要条項(責任上限・IP・機密・解除)の変更は弁護士レビューを必須**とする。SemVer管理・旧版はarchive(不削除) |
| 法務レビュー | 定時=年次総会で全雛形を点検(法改正反映)。臨時=紛争発生時・新類型追加時・L6締結時(T-07は毎回) |
| 緊急契約 | 緊急案件でも雛形外の即席契約を作らない。間に合わない場合は「基本契約+最小の個別注文書(範囲・金額・納期・検収のみ)」で締結し、詳細別紙を7日以内に追完する。**緊急を理由とする重要条項(責任・IP・収穫)の削除を禁止する** |
| ライフサイクル | 起案→検証(4点)→締結(H)→履行→検収→完了(収穫)→保存7年→archive。全状態をSTATEの契約台帳で追跡し、更新期日・解約通知期限は配管がリマインドする(通知はR・判断はH) |
| アーカイブ | 終了契約は削除せずarchiveへ。紛争可能性のある案件は時効期間を考慮して保存延長(弁護士助言に従う) |
