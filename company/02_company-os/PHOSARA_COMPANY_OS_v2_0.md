# 第1部 憲法核(継承+顧客定義)

## 1.1 理念(Master Contextの要旨・参照)

PHOSARAは、φῶς(光)を名の核に持つAI Creative Tech Companyである。**見えない価値を、見える光に変える。** 三本柱=可視化・越境・本質。声=静か・明晰・断定。詳細と唯一の正はMaster Contextに存する。

## 1.2 事業定義(継承)

診断が先、制作が後。事業監査(旗艦商品)を起点に、デザインコンサルティング・解決策設計・クリエイティブ制作・継続改善へと梯子(オファーラダーL1–L6)で深まる。事業ドメインD1–D5の重心配分はL1戦略決定(HQ Core §1.2)。**提供=デザイン制作・クリエイティブ開発・入稿データまで。非提供=印刷・配送・施工・建設。**

## 1.3 顧客定義(v2.0新設 — 改善仕様書CRITICAL解消)

| 項目 | 定義 |
|---|---|
| 理想顧客(ICP) | 主要4業界(建設・リフォーム・クリニック・パチンコホール)を中心とする中小事業者。①提供価値は実在するが言語化・可視化されていない ②意思決定者に直接会える規模 ③美学と職人性への敬意がある ④診断→改善の順序を受け入れる |
| 拡張顧客 | 4業界以外でも上記①〜④を満たす事業者(拡張判定はCompany OS 3条件ANDとHQ Core機会スコアリングを通過すること) |
| アンチICP | 価格のみで選ぶ/美学への不敬/診断を飛ばして制作物だけを急がせる/支払規律を守らない——RED_FLAG_RULESに該当する者。**アンチICPへの販売は、適格な顧客から工数を盗む行為として禁止する** |
| 顧客の状態管理 | 顧客状態の正はCRM(語彙7種)、会社状態の正はSTATE(不変条件) |

## 1.4 組織(継承+参照)

組織=人間(創業者)+AIエージェント13職。編成の正はHQ Core第3部(既存6職の職務本文はAGENTS.mdが正)。人間は最上位の意思決定者であり、H領域9項(HQ Core §1.8)を永久に保持する。

# 第2部 会社統治(Company Governance)

## 2.1 所有(Ownership)

| 対象 | 所有 |
|---|---|
| 会社持分 | 創業者100%。持分の変動(増資・譲渡・共同経営)は本書で最重のType 1であり、決定記録+法務専門家の関与を必須とする |
| 知的財産 | 会社に帰属(第5部)。個人アカウント名義の資産(ドメイン・リポジトリ・ツール契約)は会社移管を原則とする |
| 正典・資産 | GitHubリポジトリ`phosara/`が唯一の保管庫。全エージェントの産物は会社資産である |

## 2.2 権限(Authority)

権限の体系はHQ Core第1部を唯一の正とする(本書は重複定義しない)。会社統治として追加するのは**機関の設置**のみ:

| 機関 | 頻度 | 権限 | HQ Core接続 |
|---|---|---|---|
| 日次運転 | 毎営業日 | P0対応・実行キュー消化 | §1.3/§1.6 |
| 週次レビュー(経営会議に相当) | 毎週金曜30分 | Conflict Log裁定・昇格審査・Kill監視・手順層改定 | §2.5 |
| 月次校正(取締役会に相当) | 月末 | KPI閾値・採点重み・財務締め・依存度警告 | §2.5 |
| 四半期棚卸し(戦略会議に相当) | 四半期末 | 資産棚卸し・リスクレジスタ更新・拡張/撤退答申 | §2.5 |
| 年次総会(株主総会に相当) | 年1回 | MAJOR改版窓・価格改定・年間目標・本書の見直し | §5.5 |

## 2.3 責任(Responsibilities)と説明責任(Accountability)

1. 各システム・各工程の責任者は所有権表(HQ Core §2.2)と工程仕様(Execution OS 第2部)に定義済み。**責任のない仕事を作らない**
2. 説明責任の宛先は三者——顧客(納品と誠実)・未来の自分と従業員(記録と正典)・社会(法令と税)。全Type 1決定は決定記録(日付・理由・却下代替案)を残す
3. 失敗の責任は個人ではなくシステムに問う(品質原則の継承)。責任追及ではなく、Failure Log→再発防止のPRが唯一の清算手続きである

## 2.4 エスカレーション

E1–E5(HQ Core §1.10)を唯一の経路とする。会社統治上の追加規則: **法・税・持分・雇用に関わる疑義は、段階を飛ばして直ちにE4(人間同期)とし、必要に応じ外部専門家(税理士・弁護士等)へ接続する。** 外部専門家への相談はType 2(速度優先)、その助言に基づく決定はType 1。

# 第4部 財務運営(Financial Operations)

## 4.1 収益規則(Revenue Rules)

1. **入金主義:** 受注は収益ではない。入金のみを収益と数える(HQ Core §1.1継承)
2. 収益の三層: フロー(監査・制作の単発)/MRR(L5継続・Casebookプラン)/資産由来(テンプレート・事例が生む将来受注)。週次計器盤はフローとMRRを分けて表示する
3. 全入金はSTATEに記録し、請求→入金→消込の3状態を追跡する(配管AP-02/AP-07)

## 4.2 価格規則(Pricing Rules)

1. 価格の確定はH領域(永久)。現場値引きの禁止・変更はType 1(継承)
2. 価値基準価格: 灯した光の価値で決め、掛かった時間で決めない(Principle 4.5継承)
3. 支払条件の標準: 監査(L2)=前払い/構築(L4)=着手金50%+納品時50%/継続(L5)=月額前払い
4. **価格体系の一元管理:** オファーラダー(L1–L6)価格表と業種別プライシング(例: Casebook月額プラン=L5の業種エディション)は、単一の価格ガバナンス文書(`04_products/PRICING_GOVERNANCE`)で管理する。二重基準を作らない(統合審査M-3の恒久解)

## 4.3 投資規則(Investment Rules)

HQ Core §1.5(6項)を唯一の正とする——投資上限=月次売上見込みの10%または1万円のいずれか小(超過はType 1)・2周回収基準・無料労働の禁止。本書は重複定義しない。

## 4.4 経費規則(Expense Rules)

| 区分 | 規則 |
|---|---|
| 単発経費 5,000円未満 | R(記録のみ。STATEに1行) |
| 単発経費 5,000円以上 | A(事前に人間承認) |
| 新規の固定費(サブスク・保守契約) | Type 1に準ずる(少額でも累積するため。解約条件を決定記録に含める) |
| 全経費共通 | 領収書・請求書を会計保管(第5部の保存年限)。私費との混同を禁止する |

## 4.5 資金繰り規則(Cash Flow Rules)

1. 現金は週次計器盤の第4指標として毎週確認する
2. 3ヶ月先の入金予測を月次で更新し、**予測現金が固定費2ヶ月分を下回る見込みが立った時点でP1警報**(新規需要創出を最優先化)
3. 支払遅延30日超はKill基準の手続きへ(継承)。督促は配管(AP-07)が定型実行し、交渉はH

## 4.6 利益配分(Profit Allocation)

全入金から、次の順で即時に区分する(口座または帳簿区分で物理的に分ける):

| 順 | 区分 | 率 | 目的 |
|---|---|---|---|
| 1 | 税・公課引当 | 30% | 所得税・住民税・事業税・消費税の引当。**引当口座には手を付けない** |
| 2 | 準備金積立 | 20% | 目標=固定費6ヶ月分に達するまで積立(達成後はこの率を報酬・投資へ再配分。再配分はType 1) |
| 3 | PBOS投資枠 | 10% | 資産ループへの再投資(投資規則§4.3の枠内で執行) |
| 4 | 役員報酬・生活費 | 残余40% | 創業者の生活の持続可能性を確保する(疲弊の予約=安売りと同罪) |

※ 率の変更はType 1。初年度の暫定値であり、年次総会で校正する。

## 4.7 準備金方針(Reserve Policy)

目標=固定費6ヶ月分。用途は①事業継続(売上ゼロ月の橋渡し)②緊急対応(第6部インシデント)③好機投資(スコア35点以上かつType 1承認)の3つに限定。取り崩しは全てType 1+決定記録。

# 第5部 法務フレームワーク(Legal Framework)— v2.0新設

> 本部は運用規範である。個別案件の法的判断は外部専門家(弁護士・税理士)の助言を優先し、その助言と本書が矛盾する場合は助言に従い、本書を改版する(Conflict Log経由)。

## 5.1 知的財産(Intellectual Property)

| 対象 | 帰属・扱い |
|---|---|
| 納品物(最終成果物) | **全額入金の完了をもって**、契約に定めた利用範囲でクライアントへ権利移転または利用許諾する。入金前の権利移転を禁止する |
| 制作過程のノウハウ・テンプレート・部品・手法 | **PHOSARAに留保する**(収穫条項の法的根拠)。契約書に「受託者は本件業務を通じて得た一般的知見・手法・再利用可能な部品を自らの事業に利用できる。ただし委託者の機密情報を含まない形に限る」旨を必ず含める |
| 事例公開(ポートフォリオ利用) | 契約の収穫条項で事前合意する。開示階層(公開可/匿名可/非公開)をクライアントと確認し、公開はH承認 |
| 第三者素材(フォント・写真・コード) | ライセンスを取得・記録してから使用。ライセンス台帳を`06_assets/licenses/`に置く。出所不明素材の使用を禁止する |

## 5.2 著作権(Copyright)

1. 納品物の著作者人格権は行使しない旨を契約で定める(業界慣行)。著作財産権の移転範囲(複製・翻案・二次利用)は契約書に明記し、包括的な「全部移転」を安易に約さない
2. 他者の著作物の模倣・トレース・実質的複製を禁止する。参照と模倣の境界に疑義があれば制作を止めてE4
3. AI生成物を含む納品物は、人間の監修・選択・編集を経た成果物として権利処理する(§5.6と接続)

## 5.3 商標(Trademark)

1. 「PHOSARA」の文字・ロゴは会社の中核資産。商標出願(文字・図形、主要役務区分)を実行フェーズ初年度の法務タスクとし、費用は投資規則で審査する
2. サブブランドは「PHOSARA+機能名」方式のみ(Brand Book継承)。第三者商標との衝突調査を命名の予備審査(Branding Agent)に含める
3. クライアントの商標・ロゴは支給素材としてのみ使用し、改変にはクライアント承認を要する

## 5.4 機密保持(Confidentiality)・NDA方針

| 規則 | 内容 |
|---|---|
| 標準NDA | 相互NDA(双務)を標準とする。監査開始前(A1受注時)に締結。契約書テンプレートに機密保持条項を標準装備し、単独NDAは先方要請時のみ |

## 5.5 クライアントデータ方針(Client Data Policy)

| 項目 | 規則 |
|---|---|
| 分類 | 3層: 公開可/匿名可/非公開(開示階層と同一) |
| 保管 | 非公開データは`07_clients/`+アクセス制御された共有ドライブのみ。ローカル端末への恒久保存を禁止 |

| 個人情報 | 利用目的の明示・目的外利用の禁止・第三者提供の原則禁止(個人情報保護法)。個人情報を含む案件はSTATEにフラグを立てる |

## 5.6 AI利用方針(AI Usage Policy)— 対外・法的側面

Principle 4.8(AI活用5原則)を内部規範として継承した上で、対外・法的規範を定める:

1. **監修義務:** すべてのAI生成物は人間の監修を経てから対外化する(無検査公開の禁止・継承)。納品物の最終責任はPHOSARAが負い、「AIが作ったから」を免責に用いない
2. **開示:** 制作プロセスにAIを活用する旨を契約書・会社案内に記載する。クライアントから問われれば誠実に開示する
3. **機密データの投入条件:** クライアント機密は、①学習利用が遮断され ②契約・規約上業務利用が許可されたAIツールにのみ投入できる。条件を満たさないツールへの投入を禁止する
4. **ハルシネーション対策:** 事実の記載(監査の数値・引用・法令)は必ず一次資料と突き合わせる(三証拠源の原則をAI出力にも適用)
5. ツールの利用規約・商用利用条件をライセンス台帳で管理する

## 6.2 インシデント対応(Incident Response)

```
検知 → P0宣言(STATEに記録) → 影響範囲の特定
 → 封じ込め(アクセス遮断・公開停止)
 → 顧客・関係者への通知(24時間以内・事実のみ・誠実に)
 → 復旧 → Failure Log(根因はシステムに求める)
 → 再発防止のPR(検査項目・手順・契約の改定) → 週次レビューで完了確認
```

## 6.3 災害復旧(Disaster Recovery)

前提=正典と資産はGit+オフサイトに存在する(§5.8)。端末・回線・主要ツールのいずれを失っても、**代替端末+GitHub+STATEで1営業日以内に業務を再開できる**状態を維持する(RTO=1営業日)。四半期棚卸しで「何を失うと何日止まるか」を1行で再点検する。

# 第10部 継承計画(Succession Planning)— v2.0新設

## 10.1 継承の思想

継承の第一手段は人ではなく**正典**である。「STATEを読めば10分で全体復帰できる」状態(継承済みKPI)は、未来の従業員・後継者・AIエージェントへの最initial遺言である。書かれていない知識は継承できない。

## 10.2 新規雇用(New Employees)

| 項目 | 規則 |
|---|---|
| 雇用の決定 | Type 1(決定記録必須)。最初の採用は制作補助(Builder配下)を標準とする |
| 採用基準 | 3条件AND: ①美学への敬意 ②書く文化(記録・正典)への適合 ③H領域と承認階層の尊重 |
| 受け入れ(オンボーディング) | Day 1: Master Context→HQ Core第0〜1部→STATE/Week 1: PBOS→Execution OS→担当職のAGENTS節/Month 1: 担当実務層(Audit KitまたはWebsite Production)+Brand Book。**独り立ち条件=10分復帰テスト合格+担当タスクのA承認3回** |
| 委譲 | 従業員もH/A/Rから開始(Aスタート)。人とAIで同一規律 |
| 退場手続き | アクセス即日失効(§5.7)・貸与資産回収・引き継ぎのSTATE記録・機密保持の存続確認 |

## 10.3 パートナー(New Partners)

1. 紹介パートナー: 紹介料・条件を書面で透明化。品質責任は常にPHOSARAが負う(名を貸さない)
2. 外注パートナー: 発注書面・支払期日の法令遵守(§5.9)・成果物のIP帰属を発注書に明記・ブランド検査(Branding Agent)を納品条件に含める
3. 提携の締結・解消はType 1

## 10.4 将来の経営者(Future Executives)

H領域は原則として創業者に帰属するが、唯一の移譲手続きとして**後継者指名**を定める: ①指名はType 1の中でも最重(決定記録+書面) ②移譲はH領域を一括でなく項目ごとに段階移譲(価格→スコア確定→…の順で実績を確認しながら) ③完全移譲まで創業者は拒否権を保持 ④移譲の各段階をSTATEに記録。

## 10.5 事業継続(Business Continuity)— 創業者不能時の緊急プロトコル

| 段階 | 動作 |
|---|---|
| 発動条件 | 創業者と連絡不能7日、または本人が稼働不能を宣言 |
| 即時 | Type 1・H点の全停止(安全側・Execution OS §5.6継承)。進行案件はWIP内の実行のみ継続 |
| 72時間以内 | 進行中クライアントへの状況通知(誠実に・事実のみ)。納期影響の提示 |
| 未着手分 | 入金済み・未着手の役務は返金を原則とする(契約書の中途終了条項に定める) |
| 引き継ぎ | 正典一式(GitHub)+アクセス手順を封緘した引き継ぎ書を、信頼できる指定者に託す(指定はType 1・年次更新)。指定者は清算または継続の判断に必要な情報へ到達できる |

## 10.6 知識移転(Knowledge Transfer)

新しい人・新しいAIエージェント・新しいツールのいずれに対しても、移転手段は同一である——正典を読ませ、STATEで現在地を渡し、A承認3回で委譲を広げる。**口伝・属人・「聞けば分かる」を移転手段として認めない。**
