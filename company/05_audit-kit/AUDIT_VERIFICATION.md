# AUDIT_VERIFICATION.md — 監査品質検証(統合チェックリスト+承認点台帳)

**位置づけ:** VERIFICATION.md(60-Day System)の監査特化版。各工程の関門(ゲート)として運用し、未通過のまま次工程へ進まない。

---

## 1. 人間承認点の台帳(監査全工程)

| # | 工程 | 承認事項 | 委譲可否 |
|---|---|---|---|
| G1 | Day 0 | 実施範囲・価格の確定/依頼メール送信 | 不可 |
| G2 | Day 4 | 仮説リストのレビュー(ヒアリング重点の決定) | 不可 |
| G3 | Day 5-7 | ヒアリング実施そのもの | **永久に不可** |
| G4 | 随時 | レッドフラグの事実確認と顧客への第一報 | 不可 |
| G5 | Day 8-10 | 11モジュール・6領域スコアの確定 | **永久に不可** |
| G6 | Day 11-12 | 最優先課題1点と方向性の確定 | **永久に不可** |
| G7 | Day 13 | サマリー3行の執筆(人間の言葉)/報告書最終承認 | 不可 |
| G8 | Day 14 | 報告プレゼン/紹介依頼の実施 | 不可 |
| G9 | 事後 | 事例の形式判定・匿名化確認・公開承認 | 不可 |

※「不可」=現60日体制で委譲しない。「永久に不可」=Company OS上も自動化対象外(監査の魂)。

## 2. 工程ゲート・チェックリスト

### ゲートA: 着手前(Day 0終了時)
- [ ] 入金確認済み(未入金での着手は規律違反)
- [ ] 案件フォルダ生成・チェックリスト/テンプレ配置済み(audit-prep)
- [ ] 日程(ヒアリング・報告会)が両方確定している
- [ ] 事前シート・資料依頼が送付済み

### ゲートB: ヒアリング前(Day 4終了時)
- [ ] 技術計測完了(3回測定・測定条件記録つき)
- [ ] チェックリスト観察欄が7割以上埋まっている(全項目にエビデンス表記)
- [ ] 仮説リスト(10-15項目)を人間がレビュー済み(G2)
- [ ] 会社専用の問い(5-8個)を印刷/手元に用意
- [ ] レッドフラグ走査済み(該当時はプロトコル完了)

### ゲートC: 分析完了(Day 10終了時)
- [ ] 全11モジュールに「対話」エビデンスが最低1つある
- [ ] スコア確定済み(G5)+各スコアに代表エビデンス紐付け
- [ ] AI案と人間確定値の差分をログ記録済み(較正データ)
- [ ] 症状→構造の掘り下げが最低1段なされている

### ゲートD: 報告書提出前(Day 13終了時)= VERIFICATION 2b 完全版
- [ ] サマリー3行は人間が自分の言葉で書いたか(G7)
- [ ] 強みページ(P6)が漏出点より先にあるか/本人の言葉の引用があるか
- [ ] 優先課題は1点か/構造側から選ばれているか/選定理由3行があるか
- [ ] 方向止まりか(解決策・媒体・制作物を確定していないか)
- [ ] クイックウィン⚡が2つ以上・実施ガイド添付か/「御社で可能」を不当にPHOSARA側へ寄せていないか
- [ ] ロードマップの全項目にモジュール根拠があるか
- [ ] 次の一手は最終ページに一度だけか
- [ ] 信号・スコア・レーダー・本文の数値が完全一致か(radar-chart-gen機械照合済み)
- [ ] レッドフラグの対処状況が該当モジュールに明記されているか
- [ ] トーン検査(静か・明晰・誠実。煽り・誇張・断定的成果保証なし)

### ゲートE: クローズ(Day 14+3日以内)
- [ ] 報告書一式送付済み+30日確認の日程打診済み
- [ ] 紹介依頼を実施した(G8)/紹介キットを渡した
- [ ] フォロー予定(+7/+30/+90/+180日)を一括起票した
- [ ] 収穫完了: 業種別の学び1件以上/問い・チェック項目・QWの改訂候補/logs/記録
- [ ] 事例素材シート作成済み(形式判定はG9へ)
- [ ] STATE.md更新(計器盤・パイプライン)

## 3. 週次健全性チェックへの組込み

進行中監査がある週は、AG-6の週次検査(VERIFICATION.md §6)に「現在ゲートはどこか・滞留していないか・リードタイム14日への残日数」を追加する。
