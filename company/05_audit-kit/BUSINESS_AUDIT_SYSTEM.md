# BUSINESS_AUDIT_SYSTEM.md — PHOSARA事業監査キット v1.0(製品定義)

**位置づけ:** PHOSARA最初の有償商品(フラッグシップ)。すべての提案の土台。
**上位文書(教義・変更しない):** Business_Audit_Guide v1.0 / PHOSARA_MASTER_CONTEXT / 監査テンプレート4種
**本キットの役割:** 教義を「明日、実顧客に売って実施できる」状態にした実務実装。PBOS WF-04の中身そのもの。

---

## 1. 製品の一言定義

> **「制作の前に、事業を診断する。見えない価値がどこで生まれ、どこで失われているかを、11の窓から構造的に可視化し、最も効く一点を特定する。」**

売るのはチェックリストではない。**「何に投資すべきかの確信」**である。だから監査は報告書で終わらず、必ず「次の一手」で終わる。

## 2. 二層アーキテクチャ(教義との整合)

既存教義の**6つの事業監査領域**(戦略層)を判断の骨格として保持し、今回の**11診断モジュール**(実務層)を証拠の収集窓として配置する。モジュールの発見はすべて6領域のスコアに集約される。

```
【戦略層】6領域(教義・不変)      【実務層】11診断モジュール(本キット)
Value(価値)          ◀────────  M1 Business(事業・収益構造)
Market(市場)         ◀────────  M1 Business
Customer(顧客)       ◀────────  M1 Business / M7 Sales Funnel
Brand(ブランド)       ◀────────  M3 Brand
Communication(伝達)  ◀────────  M2 Website / M4 SEO / M5 UX /
                                  M6 Content / M7 Sales Funnel /
                                  M9 GBP / M10 SNS / M8 Recruitment(採用広報)
Organization(組織)   ◀────────  M8 Recruitment(体制) / M11 AI Utilization
```

**この構造の意味:** クライアントには「11の窓で徹底的に診ます」という網羅性を、報告では「結局この6つの構造の、この一点が問題です」という明晰さを提供する。窓は多く、結論は一点——これがプレミアム診断の型である。

## 3. 11診断モジュール一覧

| # | モジュール | 診断すること | 主な証拠源 |
|---|---|---|---|
| M1 | Business(事業) | 収益構造・強みの言語化・競争上の立ち位置・顧客像 | 対話・資料 |
| M2 | Website | サイトが事業目標と整合し、価値を伝えているか | 観察・計測 |
| M3 | Brand | 核の言語化・接点間の一貫性・差別化された立ち位置 | 観察・対話 |
| M4 | SEO | 検索からの到達可能性(技術基礎+コンテンツ資産) | 計測 |
| M5 | UX | 来訪→目的達成の迷いのなさ(導線・モバイル・速度) | 観察・計測 |
| M6 | Content | 発信物が価値を正確・明快に伝えているか(質と鮮度) | 観察 |
| M7 | Sales Funnel | 認知→興味→相談→成約の各段の漏れ(計測の有無含む) | 対話・計測 |
| M8 | Recruitment | 採用広報が「働く価値」を伝えているか/体制の属人化 | 観察・対話 |
| M9 | Google Business Profile | 地域検索での第一想起(情報鮮度・写真・口コミ対応) | 観察 |
| M10 | SNS | 発信の一貫性・継続構造・媒体でなくテーマ起点か | 観察 |
| M11 | AI Utilization | 業務のAI・自動化活用度と、導入余地(再現性の仕組み化) | 対話 |

※ 業種(建設・工務店/リフォーム/クリニック・整体/ホール)別の着眼点は各テンプレート・チェックリストに記載。M9(GBP)は地域商圏業種で特に重視。

## 4. 成果物パッケージ(顧客が受け取るもの)

1. **監査報告書**(AUDIT_REPORT_TEMPLATE準拠): サマリー/2枚のレーダー(6領域・11モジュール)/信号評価/優先課題/戦略的方向性
2. **改善ロードマップ**(IMPROVEMENT_ROADMAP_TEMPLATE準拠): 30日クイックウィン/60日土台/90日構造改善/1年戦略
3. **クイックウィン実施ガイド**: 顧客が自力でできる即効改善の手順(信頼の贈り物——これがあるから監査は「売り込みの前置き」でなく「それ自体で元が取れる商品」になる)
4. **報告プレゼン**(60分): 対面/オンラインでの読み合わせと質疑

## 5. 商品規律(これを守るから高く売れる)

- **前払い:** 入金確認が実施条件(PBOS現金規律)
- **方向まで、解決策は次工程:** 「どう直すか」の詳細設計はデザインコンサルティング(L3以降)の商品。ただしクイックウィンだけは例外として具体手順まで渡す(4-3参照)
- **全所見にエビデンス:** 観察/対話/資料/計測のいずれかの根拠なき所見は書かない
- **スコアは優劣でなく優先度:** 低スコア=劣っているではなく「改善の余地と優先度が高い」(教義準拠)
- **優先課題は一点:** 列挙は診断ではない。絞り込みが商品価値
- **監査の場で売らない:** 次の一手は報告書の最終節で静かに提示する(下記6)

## 6. PHOSARAサービスへの自然な接続(梯子の設計)

報告書の各発見は、以下の対応表で次段商品に接続される(顧客に見せる時は商品名でなく「次の一手」として記述)。

| 監査での発見パターン | 接続先(LIGHT Ladder) |
|---|---|
| ブランドの核が未言語化(M3低) | L3 スプリント: ブランド核の言語化 |
| サイトが価値を伝えていない(M2/M5/M6低) | L4 本体構築: サイト再設計 |
| 発見は多いが小粒(全体3点前後) | L3 スプリント: 最優先1点の集中改善 |
| 計測がなく判断不能(M7の計測不在) | L3 スプリント: 計測基盤の設置 |
| 発信が続かない体制(M6/M10+Organization低) | L5 継続運用: 月額の発信・改善 |
| 反復作業が多い・属人化(M11低) | L6 自動化・AI導入 |
| GBP/SNSの未整備(M9/M10低) | クイックウィン(自力)→L5で継続化 |

**規律:** 提案は監査の優先課題1点に対応するもの**のみ**。低スコアが7個あっても7個売らない。

## 7. 実施体制(人間×AI)

- 人間: ヒアリング/スコア・優先課題・方向性の確定/報告プレゼン(監査の魂)
- AI(AG-3 Auditor): 事前観察診断/技術計測(M2/M4/M5/M9の計測項目)/記録整理/報告書・ロードマップのドラフト(BUSINESS_AUDIT_SKILLS.md参照)
- 標準リードタイム: 受注→報告 **14日以内**(AUDIT_WORKFLOW.md準拠)
- 緊急の発見(セキュリティ・法令・評判等)は報告日を待たず即時連絡(RED_FLAG_RULES.md準拠)——診断の誠実さの証明
