# IMPROVEMENT_ROADMAP_TEMPLATE.md — 改善ロードマップ雛形(30日/90日/1年)

**思想:** ロードマップは「宿題リスト」ではなく「投資の順序」。3層の役割が異なる——**30日=信頼の贈り物(自力で可能)/90日=構造の改善(専門支援)/1年=戦略(方向の実装)**。
**規律:** 各項目は必ず監査の発見(モジュール番号)に紐づく。監査にない改善を突然足さない。担当欄で「御社で可能/PHOSARA支援」を正直に区別する(全部自社に誘導しない——それが信頼になる)。

---

## 第1層: 30日クイックウィン ⚡(御社だけで実施可能)

**目的:** 監査の翌週から効果が出始める即効改善。投資ゼロ〜小。**実施ガイド付きで渡す。**

| # | 施策 | 根拠(発見) | 期待効果 | 担当 | 所要 |
|---|---|---|---|---|---|
| 1 | 例: GBPの基本情報整備+写真20枚追加+全口コミへ返信 | M9-🔴 | 地域検索の表示改善・信頼回復 | 御社 | 半日 |
| 2 | 例: サイトの実績に日付と一言解説を追加 | M2-3 | 判断材料の即時強化 | 御社 | 2時間 |
| 3 | 例: 問い合わせ自動返信の設置(24時間以内応答の担保) | M7-3 | 機会損失の停止 | 御社(手順提供) | 1時間 |
| 4 | | | | | |

**典型的なクイックウィン候補(選定の引き出し):** GBP整備/口コミ返信/実績ページの鮮度回復/電話番号・営業時間の全接点統一/フォーム項目の削減/放置SNSの整理(閉じる判断含む)/写真の差し替え(スマホでも撮れる撮影ガイド提供)

## 第2層: 90日改善(構造への着手)

**目的:** 最優先課題(構造的要因)への本格着手。ここがPHOSARA支援の中心。

| # | 施策 | 根拠(発見) | 期待効果 | 担当 | 監査との接続 |
|---|---|---|---|---|---|
| 1 | 例: ブランド核の言語化スプリント | 最優先課題 | 全接点の軸の確立 | PHOSARA(L3) | P19-1 |
| 2 | 例: サイトの再設計(核を軸に) | M2/M5/M6 | 価値の判断材料化 | PHOSARA(L4) | P20方向性 |
| 3 | 例: 計測基盤の設置(何が効いたか分かる状態) | M7-2 | 以後の投資判断の精度 | PHOSARA支援+御社運用 | |

## 第3層: 1年戦略(方向の実装)

**目的:** 90日改善の上に積む中期戦略。四半期レビューで見直す前提の「現時点の設計図」。

| 四半期 | テーマ | 内容 | 判断点 |
|---|---|---|---|
| Q1 | 構造改善(第2層) | 上記の実行 | 90日レビュー |
| Q2 | 例: 発信の継続構造化 | 月次の事例発信・SNS運用体制(L5) | 反応データで媒体を取捨 |
| Q3 | 例: 採用広報の整備 | 働く価値の言語化→採用ページ | M8の緊急度による |
| Q4 | 例: 業務自動化の導入 | M11で特定した反復業務のAI化(L6) | 費用対効果の試算後 |

## 効果の見方(顧客への約束の仕方)

- 断定的な数値保証はしない。「何が・いつから・どの指標で観測できるか」を書く(例: GBP整備→2-4週で表示回数、8週で経路案内数)
- 30日後・90日後に**無料の経過確認(15分)**を設定する(WF-07フォローに組込み。関係の継続装置)

## 記入時の検証

- [ ] 全項目にモジュール根拠がある
- [ ] 30日枠に「御社で可能」が2つ以上ある(贈り物の担保)
- [ ] 90日枠は最優先課題1点に収束している(あれもこれも並べていない)
- [ ] 担当欄の「御社で可能」を不当にPHOSARA側へ寄せていない
