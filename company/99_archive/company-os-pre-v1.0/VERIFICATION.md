# VERIFICATION.md — 検証・ログ・自己改善の仕組み

**思想:** 検証は疑いではなく、速度の源泉である。チェックリストがあるから安心して速く動ける。ログがあるから同じ失敗を二度しない。

## 2. 出力別チェックリスト(Verify工程)

### 2a. 開拓文面(WF-01)
- [ ] その会社固有の観察が1点入っているか(使い回しでないか)
- [ ] 誇大な約束・煽りがないか(トーン: 静か・明晰・誠実)
- [ ] 提案が「診断(監査)」に向いているか(いきなり制作を売っていないか)
- [ ] 長すぎないか(スクロールなしで読める)

### 2b. 監査報告書(WF-04)
- [ ] 全所見にエビデンス源(観察/対話/資料)があるか
- [ ] スコアは「優劣」でなく「改善優先度」として書かれているか
- [ ] 優先課題は1点に絞られているか
- [ ] 方向性止まりか(解決策に踏み込んでいないか)
- [ ] 「次の一手」が具体的か(次段への自然な問いで終わっているか)
- [ ] サマリーは3行以内か/報告書全体がPHOSARAのトーンか

### 2c. 提案書(WF-05)
- [ ] 監査の優先課題1点と一対一対応しているか
- [ ] 価格は価格表と整合しているか(独自値引きなし)
- [ ] 範囲(やること/やらないこと)が明記されているか
- [ ] 支払条件(監査=前払/制作=着手金50%)が入っているか
- [ ] 収穫条項・事例化条項が契約に含まれる前提か

### 2d. 制作物(WF-06)= 品質4層(Company OS第10章)
- [ ] Layer 1 技術: 速度/レスポンシブ/リンク・フォーム全数/アクセシビリティ基礎(AG-5が自動検査)
- [ ] Layer 2 精度: タイポ規則/余白/デザインデータとの一致
- [ ] Layer 3 一貫性: 監査の方向性・ブランドトーンとの整合(人間)
- [ ] Layer 4 光: 「これは受け手の中に光を灯すか」(人間・永久に自動化しない)

### 2e. 公開物(事例・記事・SNS)
- [ ] 顧客の許諾範囲内か(事例化条項の確認)
- [ ] 匿名化が必要な情報は処理済みか
- [ ] トーン検査(騒がず実績を示しているか)
- [ ] 人間の公開承認を得たか

## 3. ログ形式(Learn工程・全WF共通)

### 成功ログ logs/success/YYYY-MM-DD_{wf}_{名前}.md
```
WF: / 担当: (人間/AG-x) / 所要:
何をした(2行以内):
うまくいった要因:
再利用できるもの: (→assets/へ切り出したらパスを記載)
スキル昇格カウント: n回目
```

### 失敗ログ logs/failure/YYYY-MM-DD_{wf}_{名前}.md
```
WF: / 担当:
何が起きた(事実のみ):
原因の仮説: (人・仕組み・情報のどれか)
即時対応:
再発防止: (手順改訂PRを出したらリンク)
```
**規律:** 失敗ログは責任追及に使わない(Company OS 6.1原則4: 失敗はシステムの失敗)。正直に書かれた失敗ログは、成功ログより価値が高い。

### 判断ログ logs/decisions/DR-{番号}.md
価格提示・受注可否・辞退などのType 2決定を1件1ファイルで記録(状況/選択肢/決定/理由/撤退条件)。

## 4. 検証ループ(リズム)

| 頻度 | 儀式 | 内容 | 所要 |
|---|---|---|---|
| 毎朝 | /morning | STATE.md確認→当日タスクを最終判断ルールで選別 | 10分 |
| 毎夕 | Report | STATE.md更新(計器盤・パイプライン・承認待ち) | 5分 |
| 毎週金 | 週次レビュー(WF-08) | KPI確認→収穫→スキル昇格判定→手順改訂→来週フォーカス3つ | 45分 |
| 案件クローズ時 | 収穫の儀 | 収穫チェックリスト完走がクローズの条件 | 30分 |
| Day 30 / Day 60 | フェーズレビュー | 60日計画との差分→計画修正(Type 2決定として記録) | 60分 |

## 5. Hooks推奨(.claude/hooks/)

| フック | タイミング | 動作 |
|---|---|---|
| state-reminder | セッション開始時 | STATE.mdの最終更新が24時間超なら警告を表示 |
| log-enforcer | タスク完了時 | logs/への記録が作成されたか確認、なければ促す |
| approval-gate | 送信・公開・価格を含む出力の生成時 | 「これは承認点です。人間の承認を得てから実行してください」を出力に強制付記 |
| pipeline-sync | leads/配下の変更時 | _pipeline.mdとの整合を検査(AG-6の常時版) |
| pre-commit | Gitコミット時 | 顧客名・認証情報など機密のassets/混入を検査 |
