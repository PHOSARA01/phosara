# CEO_MVP_OUTPUT — 出力仕様

版: v1.0 / 2026-07-10。**本 MVP のすべての出力は「起案・推奨」であり、確定はすべてオーナーが行う。**

---

## §1 Daily CEO Brief（毎営業日・朝バッチ）

固定 6 構造（この順序を変えない）:

```
# Daily CEO Brief — YYYY-MM-DD

## ① 会社の今日の一文
（事実）[状態を 1 文で要約 — 良くも悪くも正確に]

## ② 警告
[なければ「警告なし」と明記。あれば最上段に必ず掲載。種別・根拠・推奨対応を 1 枚化]

## ③ 承認待ち一覧
| 議題ID | 出所 | 件名 | 確信度 | 期限 | 滞留日数 |
[三点セット（事実 / 選択肢 / 推奨と理由）は CEO_APPROVAL_QUEUE.md を参照]

## ④ 計器盤 4 指標の変化
| 指標 | 先週比 | 基準線比 | 傾向 |
| 監査件数 | | | |
| 次段転換率 | | | |
| 契約率 | | | |
| Monthly Revenue | | | |
（算出値は PBOS AI 確定値。絶対値羅列禁止。変化点のみ表示）

## ⑤ 今日の一手
（推奨）[優先キュー筆頭 — P_ / 理由 1 行 / 担当 / 期限]

## ⑥ 遡及リンク
- Sales Report: [ファイルパス / エントリID]
- CS Report: [ファイルパス / エントリID]
- Knowledge Report: [ファイルパス / エントリID]
- PBOS Report: [ファイルパス / エントリID]
```

**10 分で読める分量を上限とし、超過分は削る。** 詳細は遡及リンクの先にある。

各行は（事実）または（推奨）のラベルを持つ。混在文を禁ずる。

## §3 オーナー決定の各 AI への配信（5 行書式）

```
FROM: CEO AI
TO:   [対象 AI 名]
WHAT: [オーナーが確定した決定内容（原文のまま）]
BASIS: [決定記録 DEC-YYYYMMDD-NNN を参照]
STATUS: オーナー承認済み・配信中
NEXT:  [受領確認を CEO_MVP_LOG.md に記帳すること]
```

配信の受領確認が揃うまで当該決定は EXECUTING 状態に留まる。

---

## §4 週次 Executive Review 素材（金曜朝）

- 計器盤 4 指標（PBOS AI 確定値）の週次推移
- Conflict Log 裁定案（Knowledge AI 起案の統合）
- 「次に変える一つ」候補（PBOS AI 起案の筆頭化・候補最大 3 件）
- 組織健全性横断指標（承認一発通過率・差戻し率・ログ即時性・収穫実施率）

**議題は決定可能な形（三点セット）に揃っていること。** 揃っていない議題は差戻し、翌週へ送らずに当週中に補完させる。

---

## §5 月次 Executive Review 素材（月末）

- 財務締め統合（入金・引当・3 ヶ月予測）
- KPI 閾値・採点重みの校正材料（変更確定はオーナー）
- 顧客依存度判定
- リスク台帳の月次差分
- 決定記録の月次索引（Type 1 全件の一覧）

---

## §6 決定記録（LOG への整形・保存）

4 要素すべて必須（欠落は COMPLETED にしない）:

```
決定ID: DEC-YYYYMMDD-NNN
日時: YYYY-MM-DD HH:MM
決定内容: [オーナーが確定した内容（原文のまま）]
理由: [オーナーが示した理由]
却下した代替案: [提示したが採用されなかった選択肢]
期待効果: [起案時の期待値]
実績評価期限: YYYY-MM-DD（決定日 +30 日）
関連議題ID: CE-YYYYMMDD-NNN
```
