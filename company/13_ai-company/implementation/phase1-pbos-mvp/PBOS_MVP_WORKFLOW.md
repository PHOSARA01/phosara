# PBOS_MVP_WORKFLOW — 手順書

版: v1.0 / 2026-07-04。Runtime第1〜7章のPhase 1写像。ここにない状況はRuntime本文とCONFLICT_LOG手続きに従う。

## PB-MVP-01 ハンドオフ受領(Knowledge AI)
- 入力: `pbos_handoff/` の5行書式(INPUT仕様§1)
- 検証3点: ①5行の完全性 ②**根拠実例2件以上**(1件は差戻し) ③実測への遡及リンク
- 遷移: (登録)→NEW→ANALYZING/不備は1回で差戻し(LOGに理由)

## PB-MVP-02 PBOS価値の評価(入口の一問)
- 問い: 「この知識は、60日以内の売上か、将来のPBOS資産のどちらかを前進させるか?」
- R=0かつA=0 → 見送り(理由1行でCOMPLETED。無言の消失禁止)
- 自己検証: 評価の根拠が実測か(感想・一般論を根拠にしない)

## PB-MVP-03 資産種別の分類(価値の観点)
- 種別: 工程改善 / テンプレ改善 / 話法・文面の型 / 検査項目 / 価格・商品の示唆 / 計測の追加
- 規則: Knowledge AIの形式分類を**再分類しない**(価値の観点タグを付加するのみ)

## PB-MVP-04 ROI・再現性・利益評価
- 採点(会社共通・機会スコアリング): R収益(0–5)×3+A資産(0–5)×3+S適合×2+C軽さ×1+K安全×1
- 判定: 35+=提案化/25–34=範囲を削って再採点/24以下=見送り(理由記録)
- 回収基準: 「何周(何案件)で回収するか」を明記。**2周で回収できない改善は原則見送り**
- 再現性: 「誰がやっても・次回も」成立する条件を1行で書けること(書けなければ再現性なし)

## PB-MVP-05 提案の作成(PBOS更新提案・改善提案)
- 書式: OUTPUT仕様§1(最小差分・期待事業価値・回収周回数・計測方法を必須装備)
- 総量規律: **週次は「次に変える一つ」を筆頭に最大3件**(列挙型の提出禁止)
- 規則5の執行: 同一工程に観測中(未検証)の改善がある場合、新提案は保留棚へ(多重変更の禁止)

## PB-MVP-06 Kill / Archive提案
- 対象: 2周期KPI未達+再採点25点未満の施策/12ヶ月再利用ゼロの資産
- 必須装備: **収穫計画(除去の前に何を学んだか・回収する部品・申し送り1行)**。装備なき提案は提出できない
- Archiveは削除ではない(archive区画への退役提案。削除の提案は本MVPに存在しない)

## PB-MVP-07 承認・記帳・日次報告
- オーナー判定: 採用 / 縮小採用 / 見送り。AIは判定どおり記帳し、**PBOS文書への反映は該当正典の改版手続き(人間確定)に委ねる**
- 日次報告はテンプレートに従い夕バッチで生成。欠落は欠落と明示

## 例外・停止
- 実測の欠落(EVT-DATA_GAP): 推定値で提案しない。まず計測の設置を提案する(計測コスト>期待効果なら見送り記帳)
- 採点乖離(起案者の自己採点と10点超の差): 軸別根拠を併記して人間裁定へ(平均で妥協しない)
- EMERGENCY_STOPファイルの存在時は全バッチ停止
