## 共有確信度モデル

すべての提案・分析に確信度（%）と根拠を付す。感覚での申告を禁ずる。

### 確信度の算定基準

確信度は以下の 3 要素から算定する。

| 要素 | 内容 |
|---|---|
| **証拠の数と質** | 一次情報（実測・ログ・正典）> 二次情報（推測・類推） |
| **正典との整合** | `PHOSARA_AI_COMPANY_OS_v1.md` / `HQ Core` / `Company OS v2.0` との矛盾がないか |
| **反証の有無** | 結論を否定するデータ・事例・制約が存在しないか |

### 確信度帯域と動作

| 帯域 | 意味 | 動作 |
|---|---|---|
| **90–100%** | 証拠が揃い、正典と整合し、反証が見当たらない | **自動推奨。** 承認不要領域なら実行してよい |
| **70–89%** | 概ね確からしいが、仮定が残る | **オーナー確認推奨。** 仮定を明示して確認に載せる |
| **70% 未満** | 証拠不足・矛盾あり | **再分析。** 提出せず、欠けている証拠の取得計画を先に出す |

### 確信度の記述形式

```
確信度: XX%
根拠: [証拠・正典整合・反証確認の状況を 1 行で記述]
仮定: [70–89% の場合のみ記述 — どの部分が仮定か]
```

## タスク検証チェックリスト

AI 従業員が仕事を提出する前に確認する。

### 全タスク共通

- [ ] 状態が `STATE.md` の 8 状態のいずれかに登録されているか
- [ ] トリガー ID が `WORKFLOW.md` の 9 種のいずれかに紐付いているか
- [ ] 確信度（%）と根拠が付いているか
- [ ] 7 要素報告書式（結論→証拠→優先度→リスク→一手→資産候補→やらないこと）を満たしているか

- [ ] 三点セット（事実 / 選択肢 / 推奨と理由）が揃っているか

- [ ] 不可逆操作を含む場合、明示されているか

### `COMPLETED` 遷移前

- [ ] `LEARNING` 状態を経由しているか
- [ ] 収穫記録（学び・改善候補）が `logs/` に残っているか
- [ ] Knowledge AI へのハンドオフが必要な場合、ハンドオフ 5 行が台帳に記録されているか

## 四半期監査（Audit Policy）

四半期ごとに AI 従業員の出力サンプルを遡って検査する。

### 監査項目

| 項目 | 確認内容 |
|---|---|
| 確信度の的中率 | 申告した確信度と実際の結果の一致度 |
| 承認方針の遵守 | 専権事項が適切に承認を経ているか |
| 書式の遵守 | 7 要素報告書式 / ハンドオフ 5 行 / 三点セットの使用状況 |
| LEARNING スキップの有無 | `EXECUTING` → `COMPLETED` の直接遷移がないか |
| Failure Log の記録 | 降格・故障が適切に記録されているか |

### 監査結果の活用

- 監査結果は各 AI 従業員の定義書（`../agents/*.md`）の改版材料とする
- 監査で発見した問題は Failure Log（`logs/`）に記録する
- 昇格・降格の審査材料として CEO AI が集計する

## 記憶アーキテクチャの整合確認

情報が正しい層に存在するか確認する。

```
第1層 Personal Agent Memory（揮発可）
 ↓ 完了時に昇格
第2層 Knowledge（正典・収穫資産 — 版管理）
 ↓ 計測と抽象化
第3層 PBOS（工程・基準・KPI への反映）
 ↓ 統合
第4層 Company Intelligence（判断材料の全体像）
```

**確認ポイント：**

- [ ] 事実・決定・学びが第 1 層（揮発性メモリ）にのみ存在していないか
- [ ] 第 2 層（Knowledge）へ昇格が必要な情報が滞留していないか
- [ ] 層を飛ばした記憶（個人メモ → 直接判断）が発生していないか

---

## 同一問への正典の重複禁止

同じ問いに二つの正典を許さない。矛盾を発見した場合の手順。

1. 発見した AI が `E3`（エスカレーション段 3）として CEO AI に報告
2. 暫定は上位文書（HQ Core）を適用
3. CEO AI が裁定案を週次レビューに提出
4. オーナーが確定 → Knowledge AI が記録
