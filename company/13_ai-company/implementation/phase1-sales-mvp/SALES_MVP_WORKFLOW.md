```
[START] オーナー指示 または TRG-01（日次朝バッチ）
 ↓
[Step 1] 営業対象リスト読み込み
 ↓
[Step 2] S・Aランクの優先ソート
 ↓
[Step 3] 1社の営業候補を選定
 ↓
[Step 4] Web調査項目の整理
 ↓

 ↓
[Step 6] 営業文の生成
 ↓
[Step 7] AI自己レビュー（8項目）
    ├─ 合格 → Step 8
    └─ 不合格（2回連続） → CONFLICT_LOG → オーナー相談（E4）
 ↓
[Step 8] Confidence Scoreの付与
    ├─ 70%以上 → Step 9
    └─ 70%未満 → 再調査 / CONFLICT_LOG

```

## Step 1 — 営業対象リスト読み込み

| 項目 | 内容 |
|---|---|
| 状態遷移 | — → `NEW` |
| 入力 | `company/04_sales/SALES_TARGET_LIST_TOCHIGI_v1.md` |
| 参照 | `company/04_sales/FIRST_SALES_TARGET_DECISION.md`（優先順） |

**実行内容：**

1. `SALES_TARGET_LIST_TOCHIGI_v1.md` を読み込む
2. 「今すぐ営業する対象（S・Aランク）」セクションのみを対象とする
3. 「参考掲載・今すぐ営業しない企業」セクションは除外する
4. 各社の管理IDと現在の営業フェーズを確認する

**出力：** 対象候補一覧（管理ID / 会社名 / ランク / 業種 / 初回営業方法 / 現在の状態）

## Step 2 — S・Aランクの優先ソート

| 項目 | 内容 |
|---|---|
| 状態遷移 | `NEW` → `ANALYZING` |
| 基準 | `company/04_sales/SALES_TARGET_CRITERIA.md` |

**優先順位ロジック：**

```
優先度1: Sランク（課題3項目以上確認済み）
優先度2: Aランク（改善余地あり）
同一ランク内の優先：
  - まだ接触していない会社 > 接触済みで返信待ち
  - FIRST_SALES_TARGET_DECISION.md に記載された最初の推奨企業を優先
  - 前回差し戻された営業文がある場合：理由を確認して再検討
```

**出力：** 優先順位付き候補リスト

## Step 4 — Web調査項目の整理

| 項目 | 内容 |
|---|---|
| 状態遷移 | `ANALYZING`（継続） |
| 原則 | 公開情報のみ。取得できない情報は[仮定]と明記 |

**調査項目（SALES_TARGET_CRITERIA.mdの観点から）：**

```
□ ホームページURL / 最終更新日 / 更新状況
□ SNS（Instagram / Facebook / LINE）の運用状況・最終更新
□ Googleビジネスプロフィールの登録状況・口コミ数・評点
□ 施術実績・症例・事例の掲載状況（整体院・接骨院の場合）
□ 施工実績・採用ページの有無（建築・工務店の場合）
□ CTA（問い合わせ導線）の状況
□ 採用ページの有無
□ 広告運用の有無（公開情報から確認できる範囲）
□ SALES_TARGET_LIST の既存評価と整合するか
```

**出力：** Web調査サマリー（各項目の現状 + SALES_TARGET_LIST記載との差分）

**注意：**
- SALES_TARGET_LIST に「推定」と記載されている項目はその旨を維持する
- 新情報で評価が変わる場合は`CONFLICT_LOG.md`に記録する

## Step 6 — 営業文の生成

| 項目 | 内容 |
|---|---|
| 状態遷移 | `ANALYZING`（継続） |
| 準拠 | `SALES_EXECUTION_TOOLKIT.md`（型・CTA） / `SALES_FIELD_GUIDE.md`（語彙・トーン） |
| 原則 | 制作を最初に提案しない / 値引きしない / 他社批判をしない |

**生成する営業文の構成：**

```
[件名 / 件名案（フォーム・DM送信時に使用）]
件名: [Business Audit の提案として自然な件名]

[本文]
書き出し: [相手の現状への共感・気づき — 押しつけがましくない]
      ↓
課題の提示: [Step 5 で確認した具体的な改善余地 — 断定せず、問いかけの形]
      ↓
BAの説明: [Business Auditとは何か — 60字以内で端的に]
      ↓
CTA: [無料相談・診断への誘導 — 押しつけでない1文]
      ↓
署名: [PHOSARA / 担当者名]
```

**出力：** 本文A（推奨案）/ 本文B（代替案）

**禁止事項（Runtime §12.3より）：**
- 価格・値引き・契約条件への言及
- 実在しない実績・数値の記載
- 相手の批判や競合の中傷
- 監査を飛ばした制作提案

## Step 7 — AI自己レビュー（8項目）

| 項目 | 内容 |
|---|---|
| 状態遷移 | `ANALYZING` → 合格: `READY` / 不合格: `ANALYZING`（再生成）|
| 上限 | 2回連続不合格 → `CONFLICT_LOG.md` → オーナー相談（E4） |

**自己レビューチェックリスト：**

| # | 項目 | 基準 |
|---|---|---|
| 1 | Business Audit提案になっているか | CTAがBAの無料相談・診断に向いている |
| 2 | 課題解決型になっているか | 相手の悩みへの共感が先にある。制作提案が先ではない |
| 3 | 過度な営業表現がないか | 「絶対」「今すぐ」「無料だから損はない」等の煽り表現がない |
| 4 | ブランドガイドラインに適合するか | 可視化・越境・本質の原則に反していない |
| 5 | 誤字脱字がないか | 文章として読んで違和感がない |
| 6 | SALES_EXECUTION_TOOLKITの型に準拠しているか | 構成（書き出し→課題→BA説明→CTA→署名）を満たしている |
| 7 | CTAが適切か | 1つのCTAのみ。複数のCTAを持たない |
| 8 | 相手の業種・状況に合っているか | テンプレート感がなく、この会社向けに書かれたと感じられる |

**出力：**
```
レビュー結果: [合格 / 不合格]
合格項目: [番号一覧]
不合格項目: [番号 + 理由]
修正内容: [不合格があった場合、修正した内容]
```

## Step 8 — Confidence Scoreの付与

| 項目 | 内容 |
|---|---|
| 状態遷移 | `READY`（継続） |
| モデル | `../VERIFICATION.md` §「共有確信度モデル」に準拠 |

**Confidence Scoreの算定：**

| 要素 | 確認内容 |
|---|---|
| 証拠の数と質 | リサーチ情報の一次情報比率。仮定の数 |
| 正典との整合 | SALES_EXECUTION_TOOLKIT / Runtime の型に準拠しているか |
| 反証の有無 | 除外すべき条件（競合強・既存取引等）がないか |

**申告フォーマット：**
```
Confidence Score: XX%
根拠: [上記3要素から1行で記述]
仮定: [70–89%の場合のみ — どの部分が仮定か]
```

**動作：**
- 90–100%: 承認キューへ（推奨案として提出）
- 70–89%: 承認キューへ（仮定を明示）
- 70%未満: 再調査 → Step 4 に戻る。2回連続70%未満は `CONFLICT_LOG.md`

## エラー処理

| 状況 | 対処 |
|---|---|
| リサーチ情報が公開情報から取得できない | `[仮定]` と明記したまま継続 / Confidence Scoreに反映 |
| 自己レビュー不合格が2回連続 | `CONFLICT_LOG.md` に記録 → E4でオーナーへ |
| Confidence Score 70%未満が2回連続 | `CONFLICT_LOG.md` に記録 → 企業をWAITINGへ |
| 承認SLA超過（48時間） | `OWNER_APPROVAL_QUEUE.md` の警告欄を更新 / Daily Briefの警告欄に記載 |
| 仕様の矛盾を発見 | `CONFLICT_LOG.md` に記録 → コードで回避しない |
