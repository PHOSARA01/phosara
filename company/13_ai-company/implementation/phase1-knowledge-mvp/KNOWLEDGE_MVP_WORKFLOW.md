## KN-MVP-01 Sales AI ハンドオフ受領

- 入力: Sales AI の 5 行ハンドオフ（INPUT 仕様 §1）
- 処理: 5 行の完全性検査（FROM-TO / WHAT / BASIS / STATUS / NEXT）。BASIS に原文参照の所在が明記されているか確認
- 検証 3 点: ①5 行書式の完全性 ②原文と要約の分離 ③機密・開示フラグの有無
- 遷移: （受領）→ NEW → ANALYZING / 不備は 1 回で差戻し（LOG に理由を記帳）
- 完了条件: 受領確認を STATE と LOG に記帳（記帳をもって処理責任が Knowledge AI へ移転）
- 「収穫ゼロ」の明示送信も正規の受領として記帳する（無音との区別）

## KN-MVP-02 CS AI ハンドオフ受領

- 入力: CS AI の 5 行ハンドオフ（INPUT 仕様 §2）
- 処理: KN-MVP-01 と同一検証。加えて事例素材の**開示未確定フラグ**の確認必須
- 機密検出時: 即時 confidential/ に隔離 → 匿名化案を別途作成 → 公開系への転送を停止（EVT-CONFIDENTIAL）
- 遷移: NEW → ANALYZING
- 完了条件: 受領確認を STATE と LOG に記帳

## KN-MVP-03 知識分類

- 処理: アイテムに種別（成功要因 / 失敗要因 / 顧客の言葉 / FAQ 候補 / 部品 / 記入例 / 矛盾 / 機密）を付与し、格納区画（assets / memo / confidential）を決定
- 索引付与: 「どんな時に使うか」を 1 行で記述（索引なき格納を完了と認めない）
- 重複検出時（EVT-DUPLICATE）: 同一の問いに答える資産が複数ある場合、統合案を作成 → 承認キューへ。承認前の削除・上書き禁止
- 矛盾検出時（EVT-CONFLICT）: 両記述を**原文のまま**併記 → 上位文書の暫定適用を注記 → CONFLICT_LOG へ記帳 → 週次レビューへ裁定案提出。自ら裁定して片方を書き換えない
- 遷移: ANALYZING → READY（資産 3 条件の予備検査合格 + 確信度付与）
- 自己検査 3 条件: ①出典・原文リンクの存在 ②種別の正確な付与 ③パターン化は 2 件以上の実例に基づく

## KN-MVP-04 成功パターン抽出

- 処理: 複数件の実例（最低 2 件）に共通する再現条件を言語化
- 出力書式:
  - パターン名（1 行・動詞から始める）
  - 根拠実例: [アイテム ID] × N 件
  - 再現条件: （「〜の場合に〜が有効」の形式）
  - 索引: どんな時に使うか 1 行
- 確信度付与: 2 件根拠→70–89% / 3 件以上→90%+ / 1 件のみ→提出不可
- 遷移: READY → WAITING_APPROVAL（差分と根拠を添えて承認キューへ登録）

## KN-MVP-05 失敗パターン抽出

- 処理: 根因と再発防止の型化（失敗は成功と同格の資産）
- 出力書式:
  - パターン名（「〜により〜が失敗する」の形式）
  - 根拠実例: [アイテム ID] × N 件
  - 根因: 1 文
  - 再発防止策（案）: 1〜3 文
  - 索引: どんな時に参照すべきか 1 行
- 遷移: READY → WAITING_APPROVAL

## KN-MVP-06 FAQ 更新案の起案

- 処理: 顧客質問の類型 → 承認済み回答集への追記案を作成
- 三点セット必須:
  - 事実: 該当顧客質問の原文・出現 N 件
  - 選択肢: A 案（回答文全文） / B 案（既存 FAQ の改版案）
  - 推奨と理由: どちらを採用すべきか・根拠 1 行
- 確信度付与
- 遷移: READY → WAITING_APPROVAL

## KN-MVP-07 正典昇格・文書改版案の承認キュー登録

- 対象: 正典（canon/）への格納 / Playbook・監査キット・Skills・テンプレの改版 / 開示判定 / 退役（archive 移動）・棄却の確定
- 書式: KNOWLEDGE_APPROVAL_QUEUE.md の項目書式に従う（差分全文 + 三点セット + 確信度 + 期限）
- SLA: 登録から 48 時間。超過は督促 1 回 → 日次報告の警告欄へ
- 承認後: 承認された差分のみを、承認された通りに反映する（反映時の改変禁止）
- 差戻し: 理由を記録し、同種 2 回で分類基準・抽出手順の改版候補に自動起票
- 遷移: WAITING_APPROVAL → EXECUTING（承認） / → NEW（差戻し、理由を次回インプットへ）

## KN-MVP-08 日次報告生成

- 処理: DAILY_KNOWLEDGE_REPORT_TEMPLATE.md のフォーマットに従い夕バッチで生成
- 欠落は欠落と明示する（埋めて取り繕わない）
- 提出先: CEO AI（Phase 1 ではオーナーが直接読む）
- LOG 確定: 夕バッチの完了を LOG に記帳してから STATE を最終更新

## 例外・停止

- 判定不能・未定義状況: 停止 → LOG に原文 → 承認キューに「相談」として登録（三点セット）
- 出典・原文の欠落: 提供元へ確認 1 回（WAITING・期限 7 日） → 期限切れは [仮定] ラベル付きメモとして保存（正典昇格の対象外）
- 確信度 70% 未満が 2 回連続: 人間相談へ（無限自己修正の禁止）
- EMERGENCY_STOP ファイルが存在する間、全バッチは冒頭で終了する
