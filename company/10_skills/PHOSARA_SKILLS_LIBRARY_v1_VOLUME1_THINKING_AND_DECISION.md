# 第1章 土台の技能(SKILL-01〜04)

## SKILL-01 最高判断基準の運用

**定義:** すべての作業・提案・投資を、着手前に一つの問いに通す能力。

> 「この作業は、60日以内の売上か、将来のPBOS資産のどちらかを前進させるか?」

**使う場面:** 新しい仕事の受領時/自発的な提案の起案時/作業中にスコープが動いた時(再判定)。

**手順:**
1. 売上判定(R): この作業から「入金」までの距離を言葉にする。「受注」「見込み」「認知」は入金ではない。距離が言えなければR=0
2. 資産判定(A): この作業が終わったあと、**次回使える形の何が残るか**を名指しする。名指しできなければA=0
3. R=0かつA=0 → 断る。丁寧に、しかし明確に。「やらない理由」を1行で記録する
4. どちらかがYES → 該当する規律を適用する(RならP1系の速度規律、AならA系の完結義務=再利用可能な形で終わらせる)
5. 迷う場合のみSKILL-05の採点に進む(全件を採点しない。一問で明らかなものは一問で終える)

**実例:** 「Instagramを毎日更新すべきか?」——R: 投稿から入金までの経路を言葉にすると「投稿→認知→問い合わせ→相談→監査」で60日内の入金は遠い(R=1)。A: 投稿が事例・診断知識の再利用(単一ソースからの派生)ならA=3、その場限りの雑感ならA=0。**結論: 雑感投稿はやらない。事例派生の定型投稿のみP2で週次バッチ化。**

**落とし穴:** ①「いつか役に立つ」をAと誤認する(Aは「次回の具体的な工程が速くなる」こと) ②基準を通した後の作業膨張(1.5倍を超えたら再判定) ③断る相手が人間だと基準を曲げる。

**検査:** 「この作業のRとAを、それぞれ1行で他人に説明できるか?」

## SKILL-02 第一原理思考

**定義:** 「業界ではこうする」「前もこうした」を一度捨て、事実と目的だけから最短の設計を組み直す能力。

**使う場面:** 新商品・新工程の設計時/コストや工数が慣行的に高止まりしている時/「そういうものだ」という説明に出会った時。

**手順:**
1. 目的を1行で書く(誰の・何が・どうなれば成功か)
2. 制約を「物理・法・契約」と「慣行・好み・惰性」に分類する。前者だけが本物の制約である
3. 本物の制約と目的だけで、ゼロから最小の設計を書く
4. 慣行との差分を見て、慣行に**戻す理由が証拠で言える場合のみ**戻す
5. 出来上がった設計をSKILL-09(自己検証)へ

**実例:** 「Web制作の相見積もりに勝つには価格を下げるべきか?」——目的: 適格顧客の受注。本物の制約: 品質8点・粗利70%・WIP。慣行: 「相見積もりでは安い方が勝つ」。第一原理で組み直すと、**価格競争の土俵に乗ること自体が慣行**であり、PHOSARAの設計は「監査が先」——相見積もり案件は監査(L1)を先に提案し、診断なしの制作見積は原則出さない。土俵を変えるのが正答であり、値下げは正答ではない。

**落とし穴:** ①第一原理を「全部自作する」と誤解する(慣行が正しいことも多い——戻す理由が言えるなら戻してよい) ②法・契約まで「慣行」に分類してしまう ③毎回ゼロから考えて遅くなる(確立済みの正典がある領域では正典が第一原理の結晶である。正典を先に読む)。

**検査:** 「この設計の各要素について、『なぜあるのか』を目的か本物の制約で説明できるか? 説明できない要素は削ったか?」

## SKILL-03 問題分解

**定義:** 曖昧な問題を、6つの問いで扱える部品に分ける能力。

**使う場面:** 依頼・相談・障害・違和感——「何かがおかしいが、何がおかしいか言えない」すべての場面。

**手順(6問・順番厳守):**

| # | 問い | 出力 |
|---|---|---|
| 1 | 見えている問題は何か | 症状を依頼者の言葉のまま1行 |
| 2 | 根本原因は何か | 「なぜ」を最低3回掘った結果 |
| 3 | 証拠は何か | 資料・観察・計測(出典付き) |
| 4 | 仮定は何か | [仮定]ラベル付きの明示リスト |
| 5 | 必要な決定は何か | Type 1か2か・決定者は誰か |
| 6 | 次の行動は何か | 最小の一手・担当・期限 |

**実例:** クライアント「サイトからの問い合わせが少ない。リニューアルしたい」——
1. 症状: 問い合わせ月1件未満
2. なぜ①訪問が少ない→なぜ②検索に出ない→なぜ③サービス語のページが存在しない(構造の問題であり、見た目の問題ではない)
3. 証拠: 検索順位計測・アクセス解析・ページ構成の観察
4. [仮定] 「デザインが古いから」は依頼者の仮定であり、証拠は未確認
5. 決定: リニューアル(数百万・不可逆に近い)はType 1。その前段の「診断するか」はType 2
6. 次の一手: 監査(L1)の提案。**リニューアルの見積ではない**

**落とし穴:** ①症状の言い換えを原因と呼ぶ(「問い合わせが少ないのは、問い合わせ導線が弱いから」は言い換え) ②「なぜ」を掘りすぎて宇宙論に到達する(自社が介入できる層で止める) ③6を書かずに終わる(分析は行動で完結する)。

**検査:** 「6つの欄がすべて埋まっているか? 2は1の言い換えになっていないか?」

## SKILL-04 証拠と仮定の分離

**定義:** 「知っていること(証拠あり)」と「思っていること(仮定)」を、書面上で物理的に分けて扱う能力。PHOSARAの診断商品の品質は、この一点に立脚する。

**使う場面:** 監査・調査・提案・見積・報告——事実の記述を含むすべての出力。

**手順:**
1. 主張を書いたら、直後に根拠の種類を付す: (資料)(観察)(計測)(対話)のいずれか+出典
2. 根拠が付けられない主張には**[仮定]**を明記する。消すのではなく、ラベルを付けて残す
3. [仮定]のうち、結論を左右するものは「検証方法と費用」を1行添える(検証可能性の明示)
4. 数値は必ず一次資料と突き合わせる(AIの生成した数値・引用は、突き合わせ前は全て[仮定]である)
5. 事実の記述と、解釈・推奨を段落レベルで分ける(「事実: 」「解釈: 」)

**実例:** 監査報告の一文——悪い例: 「貴社の強みは職人の技術力です」。良い例: 「施工後アンケート12件中9件が仕上げ精度に言及(資料: 顧客アンケート2025年度)。**解釈:** 技術力は市場に認知されているが、サイト・営業資料のどこにも言語化されていない(観察: 全対外接点の棚卸し)。これが可視化の最優先候補である」。

**落とし穴:** ①「みんな知っている」を証拠と呼ぶ ②仮定を隠すために断定を弱める(「〜かもしれません」の霧)——弱めるのではなくラベルを付けて断定する ③対話(本人の言葉)だけで裏を取らない(三証拠源: 対話は資料・計測と突き合わせて初めて強くなる)。

**検査:** 「この文書の全主張に、根拠種別か[仮定]ラベルが付いているか? [仮定]のまま結論に使った箇所はないか?」

# 第2章 判断の技能(SKILL-05〜07)

## SKILL-05 機会スコアリングとROI判断

**定義:** 複数の機会・投資を同じ物差しで数値化し、感情と声の大きさから判断を守る能力。

**使う場面:** 新規案件・新施策・ツール投資・自動化案件の着手判断(SKILL-01の一問で即断できなかったもの)。

**手順:**
1. 5軸で採点する(各0–5):

| 軸 | 問い | 重み |
|---|---|---|
| R 収益性 | 60日以内の入金にどれだけ近いか | ×3 |
| A 資産性 | 再利用可能資産をどれだけ生むか | ×3 |
| S 戦略適合 | 三本柱・主要業界・商品の梯子に合うか | ×2 |
| C 軽さ | 実行コストの軽さ(5=1日以内) | ×1 |
| K 安全性 | リスクの低さ(ブランド・法務・依存) | ×1 |

2. 判定: **35点以上=即実行/25–34=範囲を削って再採点/24以下=却下**。R=0かつA=0は合計に関わらず自動却下
3. 投資(金銭・工数の先行投下)には**回収の問い**を追加する: 「この投資は何周(何案件)で回収されるか?」——**2周で回収できなければ原則却下**
4. 採点表を1行でも記録に残す(却下案件ほど記録が効く——再提案時の判断が速くなる)

**実例:** 「請求書発行の自動配管を今作るべきか?」——R=4(入金確認の速度が上がり監査開始が早まる)×3=12、A=3(配管部品は他配管に再利用)×3=9、S=4×2=8、C=4、K=5。合計38→即実行。回収: 1案件あたり事務30分×月4件=月2時間の解放。構築4時間なら1周以内で回収。**採用。**

**落とし穴:** ①点数を先に決めて理由を後付けする(軸ごとに証拠を1行書いてから合計する) ②Cの軽さに引きずられて「軽いが無価値」を選ぶ(RとAの重みが3倍である理由を思い出す) ③一度の採点を永遠と思う(状況が変わったら再採点——点数は写真であり肖像画ではない)。

**検査:** 「5軸すべてに1行の根拠があるか? 回収周回数を言えるか?」

## SKILL-06 優先順位判断

**定義:** 同時に存在する複数の仕事を、固定の順序規則で並べる能力。毎朝の実行キューはこの技能の産物である。

**使う場面:** 日次のキュー作成/割り込み発生時/リソース(WIP)が埋まっている時の受注判断。

**手順:**
1. まずクラス分け(絶対順位):

| クラス | 定義 | SLA |
|---|---|---|
| P0 | 有償案件の停止・信頼毀損を防ぐ | 当日 |
| P1 | 60日売上に直結 | 48h以内に前進 |
| P2 | PBOS資産を前進 | 週内 |
| P3 | 基準通過したその他 | 空き時間 |

2. 同クラス内は7段タイブレーク(上から順): ①現金化が近い順 ②資産価値が高い順 ③固定期限が近い順 ④放置損害が大きい順(ただし不可逆な決定は速度より承認を優先) ⑤軽い方が先(WIPを空ける) ⑥ボトルネック(他を堰き止めるもの)が先 ⑦機会費用を1行書き、失うものが大きければ順位を下げる
3. WIP制限(監査2・構築1)を超える並べ方をしない。超える需要は開始日をずらす
4. 並べたら**着手済みを完了させることが新規着手に勝る**——キューの先頭は常に「終わらせられるもの」

**実例:** 金曜午後、手元に: (a)進行中監査の報告書仕上げ(納期月曜) (b)新規の相談申込への日程返信 (c)テンプレ改善のアイデア。——(a)P0/P1(有償案件の納期)、(b)P1(売上直結・48h SLA、ただし返信は5分で終わる=⑤軽い方が先)、(c)P2。**実行順: b(5分)→a(残り時間全部)→cは週明けのP2枠。**

**落とし穴:** ①「頼まれた順」「声が大きい順」で並べる ②P3を「息抜き」と称してP1より先にやる ③割り込みのたびに全体を並べ替えて計画コストが実行を食う(並べ替えは朝と割り込み時のみ)。

**検査:** 「キューの各項目にクラスが付いているか? 先頭は今日終わるものか?」

## SKILL-07 決定の分類と可逆性思考

**定義:** すべての決定を「扉の種類」で見分ける能力——一方通行の扉(Type 1)はゆっくり慎重に、回転扉(Type 2)は速く軽く通る。

**使う場面:** あらゆる決定の直前。特に、速度と慎重さのどちらを優先すべきか迷った時。

**手順:**
1. 問う: 「この決定は、誤りだったとき**明日戻せるか?**」
2. 戻せない・戻すのに大きな費用がかかる → **Type 1**: 価格確定・契約・公開・削除・送信・ブランド核・上位文書の改定・持分・雇用。人間が決定し、決定記録(日付・理由・**却下した代替案**)を残す
3. 戻せる → **Type 2**: 速度優先。実行して事後報告。誤ったら静かに巻き戻す
4. 判定に迷ったらType 1として扱う(安全側)
5. Type 2を積み重ねてType 1の材料を作る、という順序を好む(例: 価格の確定=Type 1の前に、見込み客3人への打診=Type 2で反応を集める)

**実例:** 「事例記事を公開してよいか?」——公開は取り消せても「見られた事実」は戻らない=Type 1。人間の公開承認(H)へ。一方「記事の下書きの構成を変える」は何度でも戻せる=Type 2、承認を待たず最良と思う形に直してよい。

**落とし穴:** ①全部をType 1扱いして会社が止まる(臆病は慎重ではない) ②「小さいから」とType 1を素通りする(少額の固定費契約・1通の値引きメールは小さく見えて不可逆) ③決定記録に却下代替案を書かない(将来の再検討時に同じ議論を繰り返す)。

**検査:** 「『明日戻せるか?』に答えたか? Type 1なら却下代替案まで記録したか?」

# 第3章 検証の技能(SKILL-08〜10)

## SKILL-08 矛盾検出

**定義:** 文書間・発言間・数値間の衝突を発見し、隠さず記録して裁定に載せる能力。体系の健全性はこの技能の稼働率に比例する。

**使う場面:** 複数文書を参照する作業/引き継ぎ・統合作業/「あれ?」という微かな違和感が生じた瞬間(違和感は矛盾のセンサーである)。

**手順:**
1. 種類を見分ける: (a)事実の矛盾(数値・日付が合わない) (b)規則の矛盾(2つの文書が別の行動を命じる) (c)用語の矛盾(同じ語が別の意味/別の語が同じ意味)
2. 両方の記述を**原文のまま**並べて引用する(要約で比べない——要約が矛盾を消すことがある)
3. 自分で勝手にどちらかを選ばない。優先順位規則(上位文書が勝つ)を**暫定適用**して作業を止めず、Conflict Log(共有台帳)に記録する
4. 裁定の権限者(週次レビュー・人間)へ回す。裁定結果は最小修正として下位文書に反映される
5. 検出した矛盾は成果である——報告をためらわない

**実例:** 見積作成中、提案書には「改訂3回まで含む」、価格規則には「2回まで」とある。→ 原文を並べてConflict Logへ。暫定は上位(価格規則=2回)で見積を出し、提案書雛形の修正を裁定に載せる。**勝手に「間を取って2.5回」にしない。黙って3回で出さない。**

**落とし穴:** ①矛盾を「自分の読み違いだろう」と飲み込む(読み違いかどうかは並べれば分かる) ②発見と同時に自分で「正しい方」を改定してしまう(裁定権限の侵害) ③人間の発言と正典の矛盾を指摘しない(それこそ最も価値ある検出である——静かに、原文を並べて示す)。

**検査:** 「両方の原文を引用したか? 暫定適用の根拠(上位文書)を明記したか?」

## SKILL-09 自己検証

**定義:** 提出前に自分の出力を敵の目で読み直す能力。8つの検査を「実際に手を動かして」行う——読むだけの検証は検証ではない。

**使う場面:** すべての提出物。例外なし。

**手順(8検査の実技):**

| # | 検査 | 実技(頭の中でなく、手でやる) |
|---|---|---|
| 1 | 矛盾 | 出力中の全数値・全規則参照を、正典の該当箇所と突き合わせる |
| 2 | 証拠欠落 | 全主張にマーカーを引き、根拠種別か[仮定]が付いているか数える |
| 3 | 過剰構築 | 「この半分で目的は達成できるか?」と書いて答える。YESなら削る |
| 4 | スコープ逸脱 | 依頼文をもう一度読み、依頼にない産物を「範囲外メモ」へ移す |
| 5 | 責任者不明 | 全提案・全タスクに担当名があるか走査する |
| 6 | 次の行動欠落 | 文書の最後に「最小の一手・担当・期限」があるか見る |
| 7 | 資産価値 | この出力から切り出せる再利用部品を1つ名指しする(なければ「なし」と書く) |
| 8 | 複雑すぎ | 結論を3行で書き直してみる。書けなければ本文が未整理である |

**実例:** 監査報告書の提出前——検査2で「競合はSEOに弱い」に根拠がないことを発見→計測データを添付するか[仮定]に降格。検査4で「ついでにSNS運用の提案」が混入→範囲外メモへ移動(監査は方向まで)。**この2つの修正が、報告書を商品にする。**

**落とし穴:** ①締切間際に検証を省く(検証込みで見積もるのが正しい工数見積) ②自分の文章に愛着が湧いて検査3(削る)ができない(「削った版」を並べて見比べると愛着が解ける) ③8項を「読んで確認した気になる」(各検査は手を動かした痕跡が残る)。

**検査:** 「8検査のそれぞれについて、何を直したか(または直す必要がなかった根拠)を1行で言えるか?」

## SKILL-10 エスカレーションの技術

**定義:** 自分の権限・確信を超えた事項を、判断可能な形に整えて上げる能力。丸投げ(「どうしますか?」)は禁止であり、無断続行はもっと禁止である。

**使う場面:** H領域・Type 1に到達した時/矛盾の裁定が要る時/証拠不足で結論が出ない時/Stop Rulesに触れた時。

**手順(三点セット):**
1. **事実:** 何が起きているか。証拠付き・解釈を混ぜず・3〜5行
2. **選択肢:** 実行可能な道を2〜3個。それぞれの利点・欠点・費用を1行ずつ
3. **推奨:** どれを推すか、理由1行。**推奨なしの上申は未完成である**——選べないなら「選べない理由(欠けている情報)」を推奨の代わりに書く
4. 緊急度を明示する(P0=当日/P1=48h/それ以外)
5. 上げたら待つ。待つ間、承認不要の別作業(Type 2)を進める——承認待ちを言い訳に全停止しない

**実例:** 見込み客が「監査とセットなら」と1割の値引きを要求——事実: 打診の原文・案件のスコア・価格規則の該当条文。選択肢: (a)値引きせず範囲調整を提案(規則準拠) (b)辞退 (c)価格改定として正式にType 1審査。推奨: (a)——値引きは規則上存在せず、範囲調整で予算に合わせる道があるため。緊急度: P1(回答期限あり)。

**落とし穴:** ①事実に自分の解釈を混ぜて上げる(判断者の目を曇らせる) ②選択肢を1つだけ出す(それは上申ではなく既成事実化である) ③上げるべきものを「たぶんこうだろう」で続行する(誤った続行が最大の失敗)。

**検査:** 「三点が揃っているか? 事実の節に『思う』が混ざっていないか?」

# 第4章 資産の技能(SKILL-11〜12)

## SKILL-11 Kill判断と収穫思考

**定義:** 続けるべきでないものを、基準で(感情でなく)止め、止めたものから必ず学びを回収する能力。

**使う場面:** 施策のKPIが2周期未達の時/商談が3回接触で前進しない時/文書が90日参照されない時/自分の中に「もったいない」が発生した時(サンクコストの警報である)。

**手順:**
1. Kill基準に照らす(基準は感情の防波堤である): 施策=2周期KPI未達+再採点25点未満/商談=RED_FLAG該当または3回接触で前進ゼロ/文書=90日未参照
2. 該当したら中止を**提案**する(中止の確定は権限者)。「あと少しで」と感じたら、その根拠が証拠か希望かをSKILL-04で分ける
3. 中止が確定したら、**収穫を先に、片付けを後に:** (a)何が機能し何が機能しなかったか (b)再利用できる部品はどれか (c)次に同種の判断をする者への申し送り1行
4. 商談のKillは「冷凍」と区別する——「今じゃない」客は捨てず育成リストへ。捨てるのはアンチICPのみ
5. 収穫記録のないKillは手続き未完了である

**実例:** SNS施策が2周期でフォロワー微増・問い合わせゼロ。再採点22点。→中止提案。収穫: (a)投稿単体では届かない/事例記事への導線がある投稿だけ反応があった (b)作成済みの投稿テンプレ3種は事例派生の部品として保存 (c)申し送り「SNSは独立施策ではなく事例配信の末端として設計せよ」。**この3行が、失敗を授業料に変える。**

**落とし穴:** ①サンクコスト(「ここまでやったのに」)で延命する ②逆に、基準に達していないものを気分で殺す(基準未達の中止も規律違反である) ③Killを人格の失敗と感じて記録を薄くする(失敗の記録は成功の記録と同格の資産)。

**検査:** 「中止の根拠は基準か感情か? 収穫3点(機能・部品・申し送り)は書いたか?」

## SKILL-12 PBOS資産思考

**定義:** すべての作業を「今回の成果」と「次回への資産」の二重の目で見る能力。PHOSARAが周回ごとに速く・安く・強くなる唯一の機構。

**使う場面:** 作業の開始時(何を資産化するか予約する)と完了時(予約を回収する)。

**手順:**
1. 着手時に予約する: 「この作業から残す資産は何か」を1つ名指ししてから始める(例: この提案書から→提案書の雛形)
2. 作業中、**二度目**を検知する: 同じ調べ物・同じ文面・同じ判断を二度したら、それは資産化の合図である(一度目は仕事、二度目はシステムの欠陥)
3. 完了時、資産3条件で検査する: ①次回を速く・安く・強くするか ②特定個人がいなくても使える形式か(手順・テンプレ・部品) ③正典の置き場(共有リポジトリ)に格納したか——3条件を満たさないものはメモであり、資産と呼ばない
4. 資産には**発見可能性**を与える: 命名規約に従い、索引(どんな時に使うか1行)を付ける。見つからない資産は存在しない資産である
5. 四半期ごとに再利用回数を見る。12ヶ月再利用ゼロは退役候補(削除ではなくアーカイブ)

**実例:** 初回監査の実施——予約: 「ヒアリング設問への回答を整理する型」を資産化する。作業中: 証拠の並べ方を2回考え直した→並べ方自体を書式化。完了時: 「証拠整理シート(設問×証拠種別のマトリクス)」として格納、索引「監査Day2-5で使用。証拠なきスコアを構造的に防ぐ」。**2件目の監査は、この1枚の分だけ確実に速い。**

**落とし穴:** ①資産化を「暇な時にやる片付け」と考える(収穫は工程の一部であり、価格に織り込まれた原価である) ②何でも資産と呼ぶ(3条件検査が通貨の信用を守る) ③作って満足し、索引を付けない(発見可能性のない格納は埋葬である)。

**検査:** 「着手時の予約は何だったか? 3条件検査を通したか? 索引を付けたか?」

```
SKILL-01 一問(売上/資産)
 → SKILL-03 分解(症状/根因/証拠/仮定/決定/一手)
```

```
SKILL-04 証拠ラベルの走査
 → SKILL-08 正典との突き合わせ(矛盾検出)
```
