## SKILL-13 傾聴(Client Listening)

### Definition
相手の言葉を、遮らず・言い換えず・評価せずに受け取り、語られた内容と語られなかった内容の両方を記録する技能。

### Purpose
診断業の原材料は相手の言葉である。傾聴の質が監査の質の上限を決める。また、中小企業の経営者は「売り込まれる」ことに慣れており、「聴かれる」ことに慣れていない。聴くこと自体が最初の差別化である。

### When to Use
無料相談・ヒアリング・検収面談・定期レビュー。相手が話しているすべての時間。

### Step-by-Step Method
1. 相手が話し始めたら、最低でも相手が自然に止まるまで遮らない。沈黙が生じても3秒は待つ(続きが出ることが多い)
2. 記録は相手の言葉のまま取る。要約・翻訳をその場で行わない(「つまり〜ですね」と先回りしない)
3. 感情の語(困っている・悔しい・不安)が出たら、その語を含む文を必ず原文で残す。感情の語は課題の座標である
4. 語られなかったことを別欄に記す(例: 売上の話はするが利益の話をしない、競合の名を避ける)
5. 相手の発言が終わってから、事実確認の質問だけを返す。助言・解決策をこの段階で言わない

### PHOSARA Example
リフォーム会社の社長が「うちは紹介だけでやってきた。ホームページなんて要らないと思っていたが、息子が作れと言う」と語った。傾聴の記録は、この原文と「本人の動機ではなく息子の圧力である」という観察、そして「紹介が減っている事実には触れなかった」という不在の記録から成る。この三点が後の監査で、施策の前に「事業承継と顧客基盤の高齢化」という本題を開く鍵になった。

### Common Mistakes
相手の話を自分の商品カテゴリーに翻訳しながら聞く(「それはサイトの問題ですね」)。メモに解釈を混ぜて原文を失う。沈黙に耐えられず質問を重ねて相手の思考を断つ。

### Self Check
原文のままの引用が最低5つあるか。感情の語を含む文を残したか。語られなかったことの欄が空欄でないか。この段階で解決策を一度も口にしていないか。

### AI Adaptation
対話の実施は人間が行う(不変)。AIは録音・記録の逐語化、感情語の抽出、不在項目(業界標準で通常語られるのに語られなかった話題)の検出を担う。AIが逐語記録を要約する場合も、原文は必ず別層で全文保存し、要約から原文へ遡れる状態を保つ。

## SKILL-14 能動的質問(Active Questioning)

### Definition
相手の頭の中にあるが整理されていない情報を、順序立てた質問で外に出す技能。尋問ではなく、相手が「話しながら自分で気づく」構造を作る。

### Purpose
経営者は自社の課題を「知っているが言語化できていない」ことが多い。質問の設計が、監査の証拠と、相手の当事者意識の両方を生む。

### When to Use
無料相談の後半・監査ヒアリング・提案前の確認・検収時の振り返り。

### Step-by-Step Method
1. 事実→数値→解釈→感情の順に降りる。いきなり「なぜ」を聞かない(防御を生む)
2. 事実の質問: 「新規のお客様は、直近ではどこから来ましたか」(最近の具体的な1件から始める)
3. 数値の質問: 「月に何件くらいですか。3年前と比べてどうですか」(比較を必ず付ける)
4. 解釈の質問: 「それはなぜだと思われますか」(本人の仮説を証拠として記録する。正否はまだ判定しない)
5. 感情の質問: 「その状況を、率直にどう感じておられますか」
6. 閉じる前に「まだ伺っていないことで、話しておきたいことはありますか」を必ず置く
7. 一度に一問。二重質問(「AとBはどうですか」)を禁じる

### PHOSARA Example
クリニックの院長への質問連鎖。「直近の新患はどこで当院を知りましたか」(事実)→「新患は月何名で、開院時と比べると」(数値: 40名→22名)→「減少の理由をどうお考えですか」(解釈: 「近隣に新しい医院ができた」)→「率直にどう感じていますか」(感情: 「うちの丁寧さが伝わっていない気がして悔しい」)。この最後の一文「丁寧さが伝わっていない」が、後の可視化提案の背骨になった。

### Common Mistakes
仮説を誘導する質問(「サイトが古いから減ったのでは?」)。数値を聞かずに解釈へ飛ぶ。質問リストを埋めること自体が目的化し、答えの中の新しい糸を追わない。

### Self Check
事実→数値→解釈→感情の順を守ったか。本人の仮説を(正否の判定抜きで)記録したか。最後の開放質問を置いたか。

### AI Adaptation
質問体系の設計・順序の維持・回答に応じた追問候補の提示はAIが担える。ただし質問の投げかけと場の判断(どこで深追いを止めるか)は人間が行う。AIは対話後、未回答の設問と浅い回答(数値なき解釈)を一覧化し、追加確認の候補として人間に渡す。

## SKILL-15 無料相談の運営(The First Thirty Minutes)

### Definition
30〜45分の無料相談を「選別」と「信頼」の二目的で運営する技能。売る場ではなく、診る場である。

### Purpose
無料相談は商品ではなく装置である。適格な相手には監査への自然な入口となり、不適格な相手には互いの時間を守る出口となる。ここで売り込めば診断業の信頼が死に、ここで無限に助言すれば無償労働が始まる。

### When to Use
すべての新規接点の最初の面談。例外を作らない(紹介客も同じ入口を通す)。

### Step-by-Step Method
1. 冒頭2分で枠を宣言する: 「今日は30分で、現状を伺い、当社がお役に立てるかどうかを一緒に判断する時間です。売り込みはしません」
2. 20分は傾聴と質問(SKILL-13・14)。事業の現状・数値・本人の仮説を集める
3. 5分で「見立ての方向」だけを返す: 課題の候補領域を1〜2点、証拠と共に指す。**処方(具体的な解決策)は言わない**
4. 残り5分で三択を提示する: (a)有償監査で全体を診断する (b)今は時期でない——半年後に再度話す (c)当社の領域ではない——可能なら適切な先を紹介する
5. その場で契約を迫らない。監査の説明資料と価格を渡し、判断の期日だけ合意する
6. 終了後10分以内に、相談記録(原文・数値・判定)を台帳に残す

### PHOSARA Example
建設会社との無料相談。20分の傾聴で「元請け依存率が高く、単価決定権がない」という数値が出た。見立ては「サイト以前に、直請け比率という事業構造の課題がある」とだけ伝え、工法ページの改善案など具体策には触れない。社長は「サイトを作ってくれと言うつもりで来たが、診てもらう方が先だと分かった」と述べ、1週間後に監査を申し込んだ。売らなかったことが売った。

### Common Mistakes
30分で解決策を語り尽くしてしまう(無償の監査になる)。不適格の兆候を見ながら「せっかく来たから」と監査へ通す。相談時間の延長を安請け合いする(枠は信頼の一部である)。

### Self Check
冒頭の枠宣言をしたか。処方を一度も言っていないか。三択のどれかで明確に閉じたか。記録を当日中に残したか。

### AI Adaptation
日程調整・事前情報の収集(公開情報の下調べ)・相談記録の構造化・三択の結果に応じた後続処理(監査案内の送付、再接触日の登録)はAIが担う。相談そのものの実施と三択の提示判断は人間が行う。

## SKILL-16 適格判定(Qualification)

### Definition
相手が理想顧客(ICP)か、不適格(アンチICP)かを、基準に照らして判定する技能。

### Purpose
不適格な相手に使う工数は、適格な相手から盗んだ工数である。判定の甘さは、後工程のすべて(監査の難航・支払トラブル・値引き圧力)として返ってくる。

### When to Use
問い合わせ受付時(一次判定)・無料相談後(本判定)・案件進行中に兆候が出た時(再判定)。

### Step-by-Step Method
1. 適格の四条件に照らす: 提供価値が実在するが言語化されていない/意思決定者に直接会える/美学と職人性への敬意がある/診断から始める順序を受け入れる
2. 不適格の兆候に照らす: 価格だけを問う・美学への不敬・診断を飛ばして制作物だけを急がせる・支払条件への抵抗
3. 判定は三値で行う: 適格(監査へ)/保留(育成へ——今は時期でないだけ)/不適格(丁重に辞退)
4. 保留と不適格を混同しない。保留は資産(将来の顧客)、不適格は判定の完了である
5. 判定理由を一行で記録する。理由なき判定は再現できない

### PHOSARA Example
パチンコホール2店からの同週の問い合わせ。A店: 「販促物の質を上げたい。まず店を見てほしい」——適格(順序の受容・現場への招待は敬意の表れ)。B店: 「今のデザイン会社より安ければ乗り換える」——不適格の一次兆候(価格のみ)。B店には月額プランの資料送付のみで深追いせず、A店に相談枠を充てた。3ヶ月後、A店はSTANDARDプランを継続中、B店は他社と価格交渉を続けていると聞いた。

### Common Mistakes
売上が欲しい時期に基準を緩める(基準は好況時ではなく不況時のためにある)。一つの良い兆候で全体を上書きする(四条件は個別に見る)。不適格の通知を曖昧にして相手の時間も奪う。

### Self Check
四条件を個別に判定したか。三値(適格・保留・不適格)のどれかを明記したか。理由を一行残したか。

### AI Adaptation
公開情報による事前スクリーニング、問い合わせ文面からの兆候検出、判定記録の台帳化はAIが担う。最終判定、特に「不適格」の確定と通知は人間が承認する(誤判定の代償が大きい側に人間を置く)。

## SKILL-17 事業課題の特定(Business Problem Identification)

### Definition
相手が持ち込む「依頼」(サイトを作りたい・チラシを変えたい)の背後にある「事業課題」(売上・利益・採用・承継)を特定する技能。

### Purpose
依頼は症状であり、課題は病である。症状に応えるだけの制作会社と、病を特定する診断会社の分岐点がこの技能である。事業課題に到達しない限り、監査は売れず、提案は値切られる。

### When to Use
無料相談・監査の序盤。相手が「作りたいもの」を口にしたすべての瞬間。

### Step-by-Step Method
1. 依頼を否定せず、依頼の目的を問う: 「そのサイトができたら、事業の何が変わっているのが理想ですか」
2. 答えを事業の言葉(売上・利益・単価・件数・人材・承継)に接続するまで問いを続ける
3. 事業の言葉に着地したら、数値で輪郭を取る: 現状値・目標値・期限
4. 課題を一文で仮置きする: 「(誰)の(何)が(どれだけ)足りない/漏れている」
5. 仮置きした課題を相手に返し、本人の言葉で修正させる(課題の共同所有)
6. この時点ではまだ原因を断定しない。原因の特定は監査(SKILL-18・19)の仕事である

### PHOSARA Example
美容室オーナーの依頼は「Instagramをおしゃれにしたい」。目的を問うと「若いお客さんを増やしたい」、さらに問うと「常連の年齢が上がり、10年後が怖い」。数値化すると新規は月6名でうち20代は1名。課題の一文は「20代新規客の獲得経路が事実上存在しない」。Instagramの装飾は症状への対処であり、課題は獲得経路の設計であることが共有された。監査の受注はこの共有の直後に決まった。

### Common Mistakes
依頼をそのまま課題と呼ぶ。事業の言葉に着地する前に施策の話へ滑る。数値の輪郭を取らずに「集客が課題」で止める(輪郭なき課題は診断できない)。

### Self Check
課題は事業の言葉で書かれているか。数値(現状・目標・期限)があるか。相手が自分の言葉で課題を言い直したか。

### AI Adaptation
業界ごとの「依頼と課題の典型対応」(例: サイト刷新の依頼の背後にある採用難)を知識として蓄積し、問いの候補を提示するのはAIの仕事。課題の一文の確定は、対話の中で人間が行う。

## SKILL-18 事業監査の実施(Business Audit Execution)

### Definition
定められた工程・モジュール・証拠規律に従い、有償監査を再現可能な品質で完遂する技能。

### Purpose
監査は旗艦商品である。実施者が変わっても、案件が変わっても、同じ深さと同じ体裁に着地することが商品性の核であり、その再現性はこの技能の運転規律から生まれる。

### When to Use
監査契約の締結・入金確認から、報告書の納品まで(内部工程14日)。

### Step-by-Step Method
1. 開始条件を確認する: 契約締結・前払い入金・範囲と除外の合意。三つ揃うまで着手しない
2. 工程を日付に固定する: ヒアリング日・中間整理日・スコア確定日・報告日を初日に予約する(日付なき工程は延びる)
3. 三証拠源で集める: 対話(ヒアリング)・資料(数値・帳票・既存制作物)・観察と計測(現場・検索・導線)。一つの源に依存しない
4. モジュール構造に従って証拠を配置する。構造の順に埋めるのであり、思いついた順に書かない
5. スコアは証拠が置かれた項目にのみ付ける。証拠なき項目は「未証明」とし、点を付けない
6. 承認点を通過してから次工程へ進む。飛ばした承認点は必ず後で高くつく
7. 報告は「現状→根拠→優先課題→方向→道筋」の順で書く。**解決策の詳細設計を書かない**(監査は方向まで)
8. 納品面談では報告書を渡すだけでなく、優先課題の一点を口頭で相手の言葉に翻訳して確認する

### PHOSARA Example
建設会社の監査。ヒアリングで「腕は負けない」という自負(対話)、施工写真1,200枚が未整理でフォルダに眠る事実(資料)、社名検索で自社サイトが存在せず口コミサイトが最上位に出る状態(計測)が揃った。三証拠が同じ方向——「実在する技術力が、外部から見えない」——を指したため、優先課題は迷いなく一点化された。証拠源が一つなら、これは社長の自己認識の追認で終わっていた。

### Common Mistakes
入金前の着手(善意が規律を壊す)。ヒアリングの熱量で証拠収集を省く。報告書に改善施策の詳細を書き込み、次工程(コンサルティング)の商品を無償で先渡しする。

### Self Check
開始三条件は揃っていたか。三証拠源すべてから証拠を取ったか。証拠なきスコアはないか。報告は方向で止まっているか。

### AI Adaptation
証拠の整理・突き合わせ・下書き・体裁の統一・工程日付の管理はAIが担う。ヒアリングの実施・スコアの確定・優先課題の確定は人間が行う(恒久)。AIは「証拠が薄い項目」「証拠源が一つしかない項目」を自動で警告する役を負う。

## SKILL-19 根本原因の発見(Root Cause Discovery in the Field)

### Definition
監査で集めた証拠と対話から、症状の連鎖を遡り、介入可能な最深の原因に到達する技能。Volume 1の分解思考を、顧客の現場データの上で実演するものである。

### Purpose
浅い原因への処方は再発する。深すぎる原因(景気・人口動態)への処方は存在しない。「介入できる最深」という一点に着地する精度が、提案の成功率と顧客の成果を決める。

### When to Use
監査の中間整理からスコア確定まで。複数の症状が同時に観測された時。

### Step-by-Step Method
1. 症状を並べ、共通の上流を探す(別々の症状が一つの原因を共有していることが多い)
2. 各症状に「なぜ」を重ねるが、遡上の停止条件を先に決める: 自社と顧客が12ヶ月以内に介入できる層で止める
3. 原因候補ごとに、支持する証拠と反する証拠の両方を並べる(反証を探さない原因分析は願望である)
4. 原因を「構造」の言葉で書く: 人を名指しせず、仕組みの欠落として記述する(「営業担当が弱い」ではなく「紹介以外の獲得経路が設計されていない」)
5. 原因と症状の連鎖図を一本の文章で書き下せることを確認する

### PHOSARA Example
リフォーム会社で、問い合わせ減・見積成約率低下・従業員の疲弊という三症状が観測された。個別に見れば三つの施策になるが、遡ると共通の上流は「紹介元だった親世代の顧客が引退し、次世代への接点が存在しない」という一つの構造だった。連鎖の文章: 「接点の世代交代が起きていないため新規が減り、少ない案件を逃せないため無理な値引きと突貫が増え、疲弊が生じている」。処方すべきは三つではなく一つである。

### Common Mistakes
最初にもっともらしい原因が見つかった時点で探索を止める。反証を集めない。介入不能な層(市場全体の縮小)まで遡って評論で終わる。人の能力を原因に指名する(構造で書けない分析は提案に変換できない)。

### Self Check
複数症状の共通上流を探したか。停止条件(12ヶ月以内に介入可能)を守ったか。反する証拠も並べたか。原因は構造の言葉か。

### AI Adaptation
症状間の相関の指摘、業界の典型連鎖パターンとの照合、反証候補の列挙はAIが強い。ただし「介入可能かどうか」の判断は顧客の資源と意思に依存するため、確定は人間が対話の文脈を踏まえて行う。

## SKILL-20 優先課題の一点化(Priority Mapping to One)

### Definition
監査で確定した複数の課題から、最初に取り組む一点を選び抜く技能。

### Purpose
中小企業の資源は一点にしか集中できない。三つの提案は三分の一ずつ実行され、すべてが中途で終わる。一点化は顧客の成果のための規律であり、同時にPHOSARAの提案が通る確率を最大化する構造でもある。

### When to Use
監査の終盤。課題一覧が完成し、報告書に落とす直前。

### Step-by-Step Method
1. 課題を「事業への影響度」で並べる。着手のしやすさで並べない(容易さは実行計画の変数であり、選定の変数ではない)
2. 上位課題について、解消された場合の変化を数値で仮置きする(粗い見積でよい。桁が合っていれば足りる)
3. 依存関係を確認する: ある課題の解消が他の課題の前提になっていないか。前提になっている課題は影響度以上の価値を持つ
4. 一点を選び、選ばれなかった課題に「なぜ今ではないか」を一行ずつ書く(捨てるのではなく、順番を与える)
5. 一点を顧客の言葉で言い直し、納品面談で本人に復唱してもらう(復唱できない優先課題は伝わっていない)

### PHOSARA Example
クリニックの監査で、課題は「新患経路の脆弱さ」「スタッフ採用難」「院内案内物の不統一」の三つに整理された。影響度では採用難が最大に見えたが、依存関係を精査すると、採用難の一因は「医院の理念と丁寧さが外部に見えないため応募が集まらない」ことにあり、新患経路の課題と同じ根(可視化の欠落)を共有していた。一点は「医院の価値の可視化」に定まり、採用と新患の両方がその下流に位置づけられた。

### Common Mistakes
顧客が気にしている課題を(影響度と無関係に)一点に選ぶ忖度。全課題を「重要」と書いて選定を放棄する。選ばなかった課題の扱いを書かず、顧客に「無視された」印象を残す。

### Self Check
影響度で並べたか。依存関係を確認したか。選ばれなかった課題に順番の理由を付けたか。顧客は一点を自分の言葉で言えたか。

### AI Adaptation
影響度の試算・依存関係の図式化・過去案件との類似照合はAIが担う。一点の確定は人間の恒久専権である。AIは確定後、選ばれなかった課題の追跡登録(将来の再提案候補)を行う。

## SKILL-21 提案書の構築(Proposal Construction)

### Definition
監査の結論を、次段の受注に翻訳する文書を構築する技能。提案書は制作物の見積ではなく、成果への道筋の提示である。

### Purpose
監査と提案の間には橋が要る。橋のない監査は「良い報告書でした」で終わり、監査のない提案は値切られる。提案書はこの橋そのものである。

### When to Use
監査納品の後、原則として14日以内(記憶と熱量が生きているうちに)。

### Step-by-Step Method
1. 冒頭は監査の優先課題の再掲から始める。新しい主張を冒頭に置かない(提案は監査の続きである)
2. 構造を固定する: 優先課題(再掲)→放置した場合の推移→到達したい状態(数値)→道筋(段階)→この提案の範囲と除外→体制と日程→価格→検収条件
3. 一提案一焦点。優先課題の一点に対する提案だけを書く。他の課題への言及は「次の段階」の節に一行で置く
4. 範囲より先に除外を書く癖を持つ(除外の明記が後の信頼を守る)
5. 価格は公式の価格体系からのみ構成する。提案書の中で価格の正当化を長く語らない(正当化は監査の証拠が既に済ませている)
6. 提出前に、監査報告書と提案書を並べ、論理の飛躍がないか突き合わせる

### PHOSARA Example
パチンコホールの監査で優先課題は「販促物の質のばらつきによる店格の毀損」だった。提案書は、その課題の再掲から始まり、到達状態を「全販促物が単一の品質基準を通過する体制」と定義し、道筋として月額プランでの運用を提示した。サイネージや周年企画の話は「次の段階」に一行。範囲の節より除外の節(印刷・施工は含まない)を先に置いた。決裁者は「何を頼んで何を頼んでいないかが初めて明確な提案だ」と評した。

### Common Mistakes
監査に書いていない新しい診断を提案書で始める。複数の商品を並べたカタログ型提案(選択肢の多さは決断の敵)。除外の記載を避けて受注を優先する(その受注は必ず紛争になる)。

### Self Check
冒頭は優先課題の再掲か。焦点は一つか。除外を明記したか。価格は公式体系の内か。監査との突き合わせをしたか。

### AI Adaptation
構造の固定・下書き・監査報告書との整合検査・体裁の統一はAIが担う。価格の確定と提出の判断は人間が行う。AIは提出後の版を保存し、成約/不成約の結果と紐づけて提案の型の改善材料にする。

## SKILL-22 価値基準の価格提示(Presenting Value-Based Price)

### Definition
定められた価格を、値札としてではなく、監査で確定した価値との対応として提示する技能。価格を決める技能ではない(価格は統治文書で確定済みである)。提示する技能である。

### Purpose
同じ価格でも、提示の順序と文脈で受け取られ方は変わる。価値の文脈なしに数字だけを見せれば、相手は市場の相場と比べる。価値の文脈の中で見せれば、相手は自社の課題の大きさと比べる。

### When to Use
提案書の価格節・価格を口頭で伝える面談。

### Step-by-Step Method
1. 価格の前に、必ず課題の金額的な輪郭を置く(監査で仮置きした数値: 失われている売上・漏れている利益)
2. 価格は一度で、明瞭に、端数まで言い切る。言い淀み・前置き(「少々高いのですが」)を禁じる
3. 価格に含まれるものと含まれないものを、価格の直後に述べる
4. 支払条件(前払い・着手金)を価格と同時に伝える。後出しにしない
5. 沈黙が来たら待つ。沈黙は拒否ではなく計算である。埋めるために値引きや追加特典を口にしない
6. 相手の反応が価格への異議なら、SKILL-23へ移る

### PHOSARA Example
建設会社への構築提案。「監査で確認した通り、御社では年間およそ数百万円規模の直請け機会が、見えないという理由だけで元請けに流れています。この構造を変える初期構築が120万円、着手金として半額の60万円を契約時に頂きます。含まれるのは設計から入稿データまで、印刷と施工は含まれません」。数字は一度、条件は同時、そして沈黙を待った。社長は30秒黙り、「安くはないが、流れている方が高い」と言った。

### Common Mistakes
価格を最後まで隠す(不信の演出になる)。価値の文脈なしに価格表を渡す。沈黙に耐えられず自分から譲歩を始める。支払条件を契約段階まで後出しする。

### Self Check
価格の前に価値の輪郭を置いたか。一度で言い切ったか。含む/含まない/支払条件を同時に伝えたか。沈黙を埋めなかったか。

### AI Adaptation
価値の輪郭の試算資料、価格節の文面標準化はAIが担う。価格の伝達と沈黙の運用は人間が行う。AIは面談記録から「価格提示の順序が守られたか」を検査項目として確認できる。

## SKILL-23 価格への異議対応(Handling Price Objections)

### Definition
「高い」「予算がない」「他社は安い」に対し、価格を守りながら関係も守る技能。値引きは存在しないため、この技能の中身は価格交渉ではなく、範囲と時期と適格性の再確認である。

### Purpose
現場の一度の値引きは、その顧客の生涯にわたる価格と、紹介先すべての価格を壊す。異議対応の目的は受注ではなく、正しい条件での受注、または正しい保留である。

### When to Use
価格提示の後、相手が価格に言及したすべての場面。

### Step-by-Step Method
1. 異議の種類を聞き分ける: (a)価値が伝わっていない (b)本当に資金がない (c)値切りの習慣・駆け引き (d)適格性の問題が今表面化した
2. (a)には価格でなく価値へ戻る: 「金額の妥当性より先に、課題の大きさの認識が合っているか確認させてください」——監査の数値へ戻る
3. (b)には範囲の調整を提示する: 「価格は変えられませんが、範囲を第一段階に絞ることはできます」——縮小した範囲と、それでも成立する成果を示す
4. (c)には静かに一度だけ立場を述べる: 「当社は値引きの仕組みを持っていません。価格が理由で見送られるなら、それは正しい判断です」——二度言わない
5. (d)なら受注を追わない。保留(時期の問題)か辞退(適格性の問題)へ、敬意をもって移る
6. どの場合も、その場で価格・条件を動かさない。動かす必要を感じたら持ち帰り、正規の手続きに載せる

### PHOSARA Example
美容室オーナーが「知り合いの制作会社なら半額でやると言っている」と述べた。種類は(c)と(a)の混合と判定。応答は「その価格でその会社に頼むのは合理的な選択肢です。当社が提供しているのは制作物ではなく、監査で特定した『20代の獲得経路の欠如』を解く道筋です。比べるなら制作費ではなく、その課題を解けるかどうかで比べてください」。値引きには触れず、比較の軸を返した。オーナーは1週間後、当初の価格で契約した。

### Common Mistakes
異議の種類を判定せず、全部に価値の説明を繰り返す(資金の問題に価値を語っても解けない)。「今回だけ」の値引き(今回だけは存在しない)。断られることを恐れて条件を曖昧に持ち帰る。

### Self Check
異議の種類を判定したか。価格を1円も動かしていないか。範囲調整の提示は正規の価格体系の内か。断る選択肢を自分に許したか。

### AI Adaptation
異議の類型判定の補助、範囲調整案(価格体系内での縮小構成)の即時生成はAIが担う。応答の実施と、辞退・保留の最終判断は人間が行う。AIは異議の記録を蓄積し、価値の伝達が弱い箇所(同じ異議が繰り返される提案の節)を改善候補として報告する。

## SKILL-24 圧力なきクロージング(Closing Without Pressure)

### Definition
相手を急がせず、しかし決断の構造(判断材料・期日・次の一歩)を明確に提供して合意に至る技能。

### Purpose
圧力による受注は、後工程での抵抗(検収の紛糾・支払遅延・関係悪化)として全額返ってくる。診断業の受注は「説得された」ではなく「自分で決めた」でなければ、その後の協働が成立しない。

### When to Use
提案・見積の提示後。相手の判断が近いすべての局面。

### Step-by-Step Method
1. 決断に必要な材料が揃っているかを相手に確認する: 「判断のために、他に必要な情報はありますか」
2. 期日を相手と共同で設定する: 「いつまでにお返事を頂けると、この日程で開始できます」——期日は圧力ではなく工程の事実として伝える
3. 決めない自由を明示する: 「見送りも正しい判断です。その場合も監査の結果は御社の資産として残ります」
4. 期日に返事がなければ一度だけ確認し、なければ保留として育成へ移す。追撃を重ねない
5. 合意が出たら、その場で次の一歩(契約書の送付日・入金期日・キックオフ候補日)を具体化して終える。「では進めましょう」で終わらせない

### PHOSARA Example
クリニックの院長は提案後2週間、返答を保留した。追撃せず、期日の前日に一通だけ「ご判断に必要な追加情報があればお送りします。開始枠は◯日まで確保しています」と送った。院長は後日「急かされなかったので、逆に自分事として考えられた」と述べて契約した。決断の速度は相手のものであり、決断の構造だけがこちらのものである。

### Common Mistakes
沈黙の期間に不安になり、値引きや特典で決断を買おうとする。「今月中なら」と偽の希少性を作る(誠実の原則に反し、一度でばれる)。合意の高揚で次の一歩を曖昧にしたまま散会する。

### Self Check
判断材料の確認をしたか。期日は工程の事実として伝えたか。見送りの自由を明示したか。合意後の一歩は日付になったか。

### AI Adaptation
判断材料の一覧化、期日管理、確認連絡の起案はAIが担う。クロージングの対話は人間が行う。AIは「追撃回数」を計測し、規律(一度だけ)からの逸脱を警告する。

## SKILL-25 信頼構築と悪い知らせの伝達(Trust Building and Bad News)

### Definition
日常の小さな約束の履行で信頼を積み、問題が起きた時には誰より早く自分から伝える技能。信頼は演出ではなく、履行と誠実の残高である。

### Purpose
診断業は相手の内部情報を預かる商売であり、信頼が商品の前提である。そして信頼の残高が最も動くのは、良い時ではなく悪い時である。悪い知らせの伝え方が、長期関係の全てを決める。

### When to Use
常時(小さな約束)。および、遅延・欠陥・見立て違いが判明した瞬間(悪い知らせ)。

### Step-by-Step Method
1. 小さな約束を明示的に作り、守る: 「明日の正午までに送ります」と言い、正午前に送る。期限のない約束をしない
2. 守れないと分かった瞬間に、期限の前に連絡する。期限後の謝罪は遅延の告白だが、期限前の連絡は管理の証明である
3. 悪い知らせは、判明から24時間以内に、こちらから、事実→影響→対応案→再発防止の順で伝える
4. 弁解と事実を混ぜない。原因の説明は求められたら行い、まず影響と対応を先に置く
5. 相手の落胆や怒りを、遮らず受け取る(SKILL-13)。防御的にならない
6. 対応の完了後、約束した再発防止が実施されたことを報告して閉じる(閉じない悪い知らせは信頼を漏らし続ける)

### PHOSARA Example
構築案件で、外部サービスの仕様変更により公開日が5営業日遅れることが判明した。判明は金曜夕方。月曜を待たず金曜のうちに電話で「事実: 公開は◯日に遅れます。影響: 御社の販促開始には間に合います。対応: 遅延分の工程を組み替え、検収期間は削りません。再発防止: 外部依存の箇所は今後、予備日を工程に含めます」と伝えた。社長の返答は「遅れの報告でこんなに安心したのは初めてだ」だった。

### Common Mistakes
悪い知らせを「まとまってから」と寝かせる(寝かせた時間分だけ信頼が減る)。良い材料と抱き合わせて薄める。原因説明(特に第三者への責任転嫁)から話し始める。

### Self Check
約束はすべて期限付きか。悪い知らせは24時間以内・自分から・順序どおりに伝えたか。再発防止の報告で閉じたか。

### AI Adaptation
約束(期限付きコミットメント)の台帳化と履行監視、悪い知らせの構造化(事実・影響・対応・再発防止の下書き)はAIが担う。伝達そのもの、特に電話・対面での第一報は人間が行う。

## SKILL-26 フォローアップと育成(Follow-up and Nurturing)

### Definition
「今ではない」相手との接点を、負担なく・価値提供として維持し、時機が来た時に最初に思い出される位置を保つ技能。

### Purpose
診断業の商談の多くは「不適格」ではなく「時期尚早」で終わる。育成なき営業は、蒔いた種を毎回捨てて新しい畑を探す農業である。育成リストは畑であり、資産である。

### When to Use
無料相談で(b)保留となった相手・提案が見送られた相手・監査のみで完了した相手・失注した相手(アンチICPを除く)。

### Step-by-Step Method
1. 保留の理由と再接触の時機を、別れる前に相手と合意する: 「決算が終わる◯月頃に、もう一度お話ししませんか」
2. 台帳に登録する: 相手・状態・理由・合意した時機・前回の要点(原文)
3. 接触の間隔は30・60・90日を基準に、合意した時機を優先する
4. 接触の中身は必ず価値提供にする: 相手の業界の事例・相手の課題に関連する知見。「その後いかがですか」だけの接触を禁じる
5. 再接触時は前回の原文から始める: 「前回『承継が気になる』と仰っていましたが」——記憶されていることが最大の価値提供である
6. 三度の接触で時機が動かなければ、間隔を年次に広げる。捨てない

### PHOSARA Example
リフォーム会社は無料相談後「繁忙期が終わったら」と保留になった。台帳に「10月再接触・関心は職人の採用」と記録。9月末、同業他社の採用事例(公開可の知見)を一枚にして送り、10月に「以前お話しされていた採用の件、事例をご覧になってどう感じましたか」から再開した。相談から5ヶ月後に監査を受注。接触は計3回、すべてに相手の課題に関する中身があった。

### Common Mistakes
保留を失注として台帳から消す。中身のない定期連絡(接触の記録だけが目的化する)。前回の内容を忘れて毎回ゼロから話す(育成ではなく再訪問である)。

### Self Check
再接触の時機を相手と合意したか。接触に価値提供の中身があるか。前回の原文から再開したか。

### AI Adaptation
台帳管理・時機の到来通知・価値提供素材(該当業界の公開知見)の候補提示・接触記録の整理はAIの主戦場である。接触文面の最終確認と、対話の実施は人間が行う。

## SKILL-27 紹介の獲得と長期関係(Referral Generation and Long-Term Relationship)

### Definition
満足を偶然の紹介に任せず、紹介が生まれる瞬間を工程として設計し、納品後の関係を年単位で育てる技能。

### Purpose
紹介は最も成約率が高く、最も価格圧力が低い需要である。そして紹介は満足の自然現象ではなく、依頼された者にしか起きない行動である。長期関係はその紹介が繰り返し生まれる土壌である。

### When to Use
納品の面談(紹介依頼の一次時機)・成果が数値で確認された時(二次時機)・定期レビュー(継続時機)。

### Step-by-Step Method
1. 紹介依頼の時機を工程に固定する: 納品面談の最後、および成果確認の面談。感情の高い瞬間に、軽く、具体的に依頼する
2. 依頼は範囲を絞って行う: 「どなたか」ではなく「同業で、御社と同じように腕はあるのに外から見えていない会社に、心当たりはありませんか」
3. 紹介の負担を最小化する: 紹介者がそのまま転送できる一枚(自社の紹介資料)を渡す。紹介者に説明の労を負わせない
4. 紹介が発生したら、結果にかかわらず紹介者へ経過と礼を報告する(報告なき紹介依頼は二度目がない)
5. 長期関係の骨格は定期レビューに置く: 頻度を契約時に合意し、レビューでは成果の数値・次の課題・(該当すれば)次段の提案を扱う
6. 関係の温度を台帳で管理する: 最終接触日・成果の状態・次の時機。記憶に頼らない

### PHOSARA Example
パチンコホールの月額プラン開始から3ヶ月、販促物の刷新後の来店指標が改善した確認面談で、「系列店や、お付き合いのあるホールで、販促の質に悩んでいる店があればご紹介ください。この一枚をそのまま渡していただければ結構です」と依頼した。翌月、同エリアの1店から「◯◯店の店長から聞いた」と連絡が入り、無料相談から監査へ進んだ。紹介の連絡を受けた即日、元の店長へ礼と経過を伝えた。

### Common Mistakes
紹介を待つ(満足していても、依頼されなければ人は動かない)。範囲を絞らない依頼(「どなたでも」は誰も想起させない)。紹介者への報告を怠り、紹介の回路を一度で閉じる。納品後の接点が請求書だけになる。

### Self Check
依頼の時機は工程どおりか。範囲を絞ったか。転送可能な一枚を渡したか。紹介者への報告をしたか。定期レビューの次回日程は決まっているか。

### AI Adaptation
紹介依頼の時機到来の通知、紹介資料の整備、紹介経路の記録、レビュー日程と台帳の管理はAIが担う。依頼の対話と、紹介者への礼は人間が行う(この二つを機械化した瞬間に、紹介の温度は死ぬ)。
