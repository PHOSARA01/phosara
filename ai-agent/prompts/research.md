# Step 4 — Web調査 タスクプロンプト

**対象:** {TARGET_NAME}（{TARGET_ID}）
**状態:** ANALYZING

---

## タスク

以下の手順で {TARGET_NAME} の Web調査を実施してください。

## 調査クエリ（この順序で、最大5クエリ）

```
クエリ1: "{TARGET_NAME} 公式サイト"
クエリ2: "{TARGET_NAME} Instagram Facebook Twitter"
クエリ3: "{TARGET_NAME} Googleマップ 口コミ"
クエリ4: "{TARGET_NAME} 採用 求人"
クエリ5: "{INDUSTRY} {AREA} ホームページ"
```

**ツール:** `mcp__brave-search__brave_web_search`

## ページ取得（公開情報のみ）

検索結果から公式サイトのURLを取得し、以下のページを `mcp__fetch__fetch` で取得する:
- トップページ
- 施工実績 / 症例・実績ページ（業種に応じて）
- 問い合わせページ

**取得できない場合:** `[仮定: 取得不可。理由: ___]` と明記して続行する。

## 調査項目

以下をすべて調査して結果を記録する:

```
□ ホームページURL
□ 最終更新日（確認できる範囲で）
□ ホームページの状態（整備済み / 更新停止 / 情報不足 / 問い合わせ導線なし）
□ Instagram: アカウント有無 / 最終更新日 / フォロワー数（確認できる範囲）
□ Facebook: アカウント有無 / 最終更新日
□ LINE公式: 登録有無
□ Googleビジネスプロフィール: 登録有無 / 口コミ数 / 評点
□ 実績・症例・事例の掲載状況
□ CTA（問い合わせ・予約導線）の有無と品質
□ 採用ページの有無
□ SALES_TARGET_LIST の既存評価との差分
```

## 出力フォーマット

```
[Web調査サマリー]
対象: {TARGET_NAME}（{TARGET_ID}）
調査日時: YYYY-MM-DD HH:MM JST

ホームページ: [URL] / [状態]
SNS:
  - Instagram: [状態 / 最終更新]
  - Facebook: [状態 / 最終更新]
  - LINE: [有無]
Googleビジネス: [登録状況 / 口コミ数 / 評点]
実績掲載: [状況]
CTA: [状況]
採用: [有無]

SALES_TARGET_LIST との差分:
  [差分があれば記述。なければ「整合している」]

[仮定]:
  [取得できなかった情報と推定理由]
```

## 注意事項

- クエリは最大5つ。消費クエリ数を記録すること
- 競合他社の調査（クエリ5）は業種相場感の把握のみ。個社の批判に使わない
- 取得できなかった情報は `[仮定]` と明記。推測で埋めない
