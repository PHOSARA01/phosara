# Design_Audit_Template_v1.0

*PHOSARA デザイン監査（デザイン監査）実務テンプレート*

---

## 本書について

本書は、PHOSARAの **デザイン監査（デザイン監査）** を実施するための **記入式テンプレート** である。概念ガイドではなく、デザインコンサルティングの現場でそのまま使用する。事業監査（事業監査）で特定された事業課題に対し、**現在のクリエイティブ資産が、その事業価値を正しく伝えているか** を評価するために用いる。

- **事業監査（事業監査）** ── 事業課題を特定する。
- **デザイン監査（デザイン監査／本書）** ── 現在のクリエイティブ資産が、事業価値を正しく可視化できているかを評価する。
- **ソリューションガイド（Solution Guides）** ── 評価結果をもとに、解決策を設計する。

本テンプレートは、主要4業界——建設・工務店／リフォーム会社／パチンコホール／クリニック・整体——のいずれにも、同一の構造のまま適用できる。

### 唯一の基準（Single Source of Truth）

本書のすべての判断は **PHOSARA_MASTER_CONTEXT_v1.0_JP.md** に従う。ブランド理念・ミッション・ビジョン・ポジショニング・コアバリュー・ブランドボイスは、本書では再定義せず、参照するのみとする。本書は 事業監査 Guide および Design Consulting Guide と一貫する。

### 監査の位置づけ（営業フロー上の位置）

```
事業監査（事業監査）          ── 何を解決すべきかを定義する
        ↓
デザイン監査（デザイン監査）← 本書    ── 現在の資産が価値を伝えているかを評価する
        ↓
Solution Guides（解決策の設計）       ── どう解決するかを設計する
```

デザイン監査は、事業監査の **下流** かつソリューション設計の **上流** に位置する。事業監査が定めた優先課題（テーマ）を起点に評価し、その結論を解決策設計のブリーフへ接続する。

---

## 使い方

1. **冒頭の監査メタ情報を記入する。** クライアント・業界・対象資産の範囲・上流の事業監査の優先課題を確定させてから着手する。
2. **12のカテゴリーを、共通の評価軸で順に評価する。** 各カテゴリーは「現状資産レビュー → 証拠 → 評価 → 改善機会 → 優先度」の順に記入する。
3. **証拠に基づいて評価する。** 印象ではなく、観察・対話・資料の三つの証拠源を突き合わせる。
4. **統合し、一点に絞る。** 全カテゴリーのスコアを統合表にまとめ、最も事業価値の高い一点をデザインブリーフへ翻訳する。
5. **行動へつなぐ。** 推奨アクションを優先度順に整理し、ソリューション設計へ引き継ぐ。

> **記入上の規律**
> 本テンプレートはクライアントの回答を含まない。すべての評価欄・証拠欄・改善欄は空欄であり、監査ごとに記入する。固定された記述（監査観点・着眼点・定義）は評価のガイドであり、書き換えない。

## 評価スケール（全カテゴリー共通）

評価は「良い／悪い」ではなく、「事業価値が見えているか／見えていないか」を問う。

| スコア | 状態 | 定義 |
|---|---|---|
| **4** | 可視化 | 事業価値が明確に伝わる。受け手が迷わず理解できる。 |
| **3** | 概ね可視化 | 価値は伝わるが、一部に揺らぎ・弱さがある。 |
| **2** | 部分的 | 断片は見えるが、核が伝わっていない／不安定。 |
| **1** | 未可視化 | 価値が伝わっていない、または誤って伝わっている。 |
| **—** | 該当なし | 当該資産が存在しない、または対象外。 |

## 評価軸（全カテゴリー共通）

各カテゴリーを、PHOSARAの三つの柱に「受け手優先」を加えた四つの軸で評価する。

| 軸 | 問い |
|---|---|
| **可視化** | 価値に輪郭が与えられているか。 |
| **本質** | 核が残り、余分が削がれているか。 |
| **一貫性** | 他の接点と表現が揃っているか。 |
| **受け手優先** | 作り手の自己満足ではなく、受け手の理解が優先されているか。 |

## 優先度の定義（全カテゴリー共通）

| 優先度 | 定義 |
|---|---|
| **高** | 事業価値への影響が大きく、放置できない。優先課題（テーマ）に直結する。 |
| **中** | 影響はあるが、緊急性は中程度。後続で対応可。 |
| **低** | 影響は限定的。優先課題の解決後に検討する。 |

## 業界文脈リファレンス（記入の判断材料・出典：MASTER_CONTEXT）

各業界で「可視化されるべき核」は異なる。評価の判断材料として参照する。

| 業界 | 可視化されるべき核 |
|---|---|
| 建設・工務店 | 施工品質・技術・信頼の可視化。価格競争に巻き込まれない価値提示。 |
| リフォーム会社 | 同質市場での差別化と信頼。施工前後（ビフォーアフター）の価値の判断材料化。 |
| パチンコホール | 品位と訴求の両立。テーマ（成果）起点の集客。規制に配慮した上質な設計。 |
| クリニック・整体 | 専門性・安心・親しみの可視化。来院のためらいの低減。地域での第一想起。 |

# Part 1｜監査概要（Audit Overview）

`DESIGN AUDIT — OVERVIEW`

デザイン監査は、クリエイティブ資産を「見た目の好み」ではなく「事業価値の可視化度」として評価する。美的評価ではなく、事業課題の診断である。事業監査が特定した課題に対し、ブランド・ビジュアル・言葉・接点が、その価値を正しく伝えているかを構造的に検証する。

評価は12のカテゴリーに沿って行い、全カテゴリーを四つの共通軸（可視化・本質・一貫性・受け手優先）で貫く。これにより、診断は属人的な所感ではなく、誰が読んでも同じ解釈になる再現可能なものになる。

# Part 2｜監査目的（Audit Objective）

`DESIGN AUDIT — OBJECTIVE`

本監査の目的は、現在の資産が事業価値を正しく可視化できているかを判定し、**最も改善効果の高い一点** を特定して、解決策設計のブリーフへ翻訳することにある。すべてを直すことは目的ではない。事業監査が定めた優先課題に最も効く一点を選び、リソースを集中させる。

## 付録：運用上の原則

本テンプレートおよび派生資料（記入済み監査・デザインブリーフ）は、以下の原則を一貫して守る。

- **事業課題を起点に評価する。** 美的好みからではなく、事業監査が定めた課題から始める。
- **デザインを「価値の可視化度」で診る。** 見た目の評価ではなく、価値が正しく伝わっているかを問う。
- **証拠に基づいて評価する。** 観察・対話・資料の三つの証拠源を突き合わせ、印象を排する。
- **スコアは優劣ではなく、優先順位のために用いる。** 評価のためではなく、改善の起点として示す。
- **削ることで強くする。** すべてを直さず、最も効く一点に絞る。
- **事業監査の下、ソリューション設計の上に位置づける。** デザイン監査の結論は、解決策設計のブリーフとなる。
- **再定義しない。** 理念・ミッション・ビジョン・ポジショニング・バリュー・ボイスは、MASTER_CONTEXT を参照する。
