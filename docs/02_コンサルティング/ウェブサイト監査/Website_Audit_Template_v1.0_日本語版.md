# Website_Audit_Template_v1.0

*PHOSARA ウェブサイト監査テンプレート（実務用 診断フォーマット）*

本テンプレートは、クライアントのウェブサイト監査（ウェブサイト監査）を実施する際に、その場で記入して用いる実務フォーマットである。ウェブサイトの提案書でも、デザインガイドでもない。判断基準は **PHOSARA_MASTER_CONTEXT_v1.0_JP.md** に、方法論は **Business_Audit_Guide_v1.0.md** に従い、デザイン監査の評価観点は **Design_Audit_Template_v1.0.md** と一貫する。

監査の目的は、**クライアントのウェブサイトが、事業価値を効果的に伝え、事業目標を支えているかを評価すること** にある。見た目の良し悪しではなく、価値が訪問者に届き、成果につながる構造になっているかを問う。

主要4業界（建設・工務店／リフォーム会社／クリニック・整体／パチンコホール）に共通して使用できる。業界固有の論点は、各領域の「業界別の着眼点（参考）」として補助的に記載しているが、実際の記入は常にクライアントの回答・観察事実・計測値で行う。

### 監査の位置づけ（営業フロー上の位置）

```
事業監査（事業監査）          ── 何を解決すべきかを定義する
        ↓
デザイン監査（デザイン監査）         ── 資産が価値を伝えているかを評価する
        ↓
ウェブサイト監査（ウェブサイト監査）← 本書 ── サイトが価値を伝え、成果を支えているかを評価する
        ↓
Solution Guides（解決策の設計）       ── どう解決するかを設計する
```

ウェブサイト監査は、デザイン監査の **下流** かつソリューション設計の **上流** に位置する。事業監査・デザイン監査が定めた優先課題（テーマ）を起点に評価し、その結論をウェブサイトブリーフとしてソリューション設計へ接続する。

## 記入の手引き

**記入の基本**
- 空欄はすべて記入欄である。診断設問・確認の観点・業界別の着眼点は、テンプレートに固定された参照情報であり、書き換えない。
- 事実と所見を区別して記入する。観察・計測された事実はエビデンス欄に、解釈は所見・メモ欄に書く。
- 評価は「良い／悪い」ではなく、「価値が伝わり、成果を支えているか／いないか」を問う。

**四つの証拠源（エビデンス）**
- **観察** ── 実際にサイトを閲覧・操作して確認した事実。
- **対話** ── ヒアリングで得られた、意思決定者・運用担当の言葉。
- **資料** ── 事業資料・既存の制作意図・運用体制の情報。
- **計測** ── アクセス解析・表示速度・各種チェックツールの値。
- 一つの証拠源に頼らず、可能な限り複数を突き合わせて記入する。

**スコアリング・ガイダンス（重要）**
スコアは、各領域の「価値がどの程度、伝わり・機能し・再現されているか」を共通の尺度で表す。**スコアは、改善の優先順位を可視化するための指標であり、サイトや企業の優劣を評価するものではない。** 低いスコアは「劣っている」ことを意味せず、「改善の余地と優先度が高い」ことを示す。

| スコア | 状態 | 改善の優先度 |
|---|---|---|
| 1 | 機能していない／価値が伝わっていない | 最優先 |
| 2 | 部分的に機能している | 高 |
| 3 | 一定程度機能している | 中 |
| 4 | 概ね機能している | 低 |
| 5 | 十分に機能し、再現・運用できる | 現状維持 |
| — | 該当なし（対象外・未実装） | 別途記載 |

**評価の共通観点**
すべての領域は、最終的に次の二点に集約して読む。①価値の可視化（事業価値が訪問者に伝わっているか）、②成果への貢献（事業目標を支える行動につながっているか）。
