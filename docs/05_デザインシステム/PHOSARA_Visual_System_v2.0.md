# 00 Visual Systemの適用範囲

本書はWebサイト専用の設計書ではありません。

**PHOSARAが制作するすべてのビジュアルに適用される思想書**です。

媒体・制作物が変わっても、本書に定めたビジュアルの思想・原則・世界観は一貫して適用します。
PHOSARAがアウトプットするすべての表現は、本書と同じ「光・静寂・本質・境界」を体現していなければなりません。

## 適用対象

| カテゴリ | 具体的な制作物の例 |
|---|---|
| **Website** | 公式サイト・業界別ページ・ランディングページ |
| **Branding** | ロゴ・ブランドガイドライン・名刺・封筒 |
| **Graphic Design** | チラシ・パンフレット・バナー・ポスター |
| **Presentation** | 提案書・Business Audit資料・Design Consulting資料 |
| **Social Media** | SNS投稿画像・ストーリーズ・サムネイル |
| **Motion Design** | UIアニメーション・モーショングラフィック・ロゴアニメーション |
| **Video** | 紹介動画・事例動画・制作実績動画 |
| **Print** | 印刷物全般・販促ツール・パチンコホール向け制作物 |

## 適用の考え方

すべての制作物において、以下を問いかけてください。

- この制作物は「**情報を照らし、本質を可視化する**」PHOSARAの使命を体現しているか
- 「**光・静寂・本質・境界**」の4概念と一致しているか
- 「**本質的・引き算**」の表現を選んでいるか
- 媒体が変わっても、PHOSARAと分かる一貫性があるか

媒体ごとの具体的な制作仕様（サイズ・解像度・フォーマット等）は、
各媒体専用のガイドラインまたはDesign System v2.0で定義予定です。

# 01 Visual Philosophy（ビジュアル思想）

## PHOSARAのビジュアルの使命

PHOSARAのビジュアルは、**情報を照らし、本質を可視化する**ために存在します。

クライアントの事業には、まだ言語化されていない価値・強み・可能性があります。
PHOSARAはその見えない価値を「光」で照らし、受け手に正しく届く形へと変換します。

デザインはその変換を担う手段です。
見た目を美しくするためではなく、**見えなかったものを見える状態にする**ために、
PHOSARAのビジュアルは設計されます。

この使命から逆算すると、デザインに必要なのは次の4つです。

- **照らすための光**：見る人の目を正しい情報へ誘導する明快さ
- **見えるための余白**：情報が呼吸できる空間
- **届くための本質**：核心だけを残した、削ぎ落とされた表現
- **越えるための境界**：前例の枠を超え、一歩先の表現を選ぶ姿勢

これが、PHOSARAのビジュアルが存在する理由です。

## PHOSARAのデザイン思想

PHOSARAという名は、**PHOS**（ギリシャ語：光）と**ARA**（祭壇・聖なる場所・境界の門）から生まれています。

光が門をくぐる——その瞬間に、見えなかったものが姿を現す。

この物語がPHOSARAのすべてのデザインの根源です。

デザインとは、**見えないものを見えるようにする行為**です。装飾ではありません。
ブランドの価値を正しく伝えるために、最小限の手段を選び抜くことが私たちの仕事です。

## ブランドの世界観

PHOSARAの視覚世界は、次の4つの概念で表されます。

| 概念 | 意味 | デザインへの反映 |
|---|---|---|
| **光（Light）** | 価値を照らし、伝わる状態をつくる | 明るく清潔な余白。光を感じる空間設計 |
| **静寂（Silence）** | 余白と静けさを設計に組み込む | 情報を絞り、余白で語らせる |
| **本質（Essence）** | 核以外を削ぎ落とす | 装飾を排除し、必要な要素のみを残す |
| **境界（Boundary）** | 既存の枠の先へ行く | 秩序ある構造の中に、一歩先の表現を |

すべてのデザイン判断は、この4概念を基準に行います。
「このデザインは光・静寂・本質・境界を体現しているか？」と問い続けることが、
PHOSARAらしいビジュアルをつくる唯一の方法です。

## 視覚的価値観

PHOSARAのデザインは、次の価値観を体現します。

- **引き算の美学**：足すのではなく、削ぐ。必要な要素だけを残す
- **秩序ある静けさ**：騒がしくない。情報が整理され、落ち着いた空間をつくる
- **読めることの優先**：文字・情報が最も美しく読める状態を最優先する
- **余白は語る**：余白はデザインの失敗ではなく、設計された静寂である
- **一貫した再現性**：どのページでも、どのデバイスでも、PHOSARAらしさが一定に保たれる

## PHOSARAのポジショニング

PHOSARA_MASTER_CONTEXTに定義された通り、PHOSARAは**「本質志向 × 一貫再現」**の象限に立ちます。

| 軸 | 一方の極 | PHOSARAの立ち位置 |
|---|---|---|
| 表現の方向 | 装飾的・足し算 | **本質的・引き算（核を残す）** |
| 再現性 | 属人的・一回性 | **仕組み化・一貫再現** |
| 関与の深さ | 言われた通り制作 | **価値の発見から関与** |

この表はビジュアル設計においても有効です。
「装飾的・足し算」のデザインはPHOSARAではありません。
「本質的・引き算」を選び続けることがPHOSARAのビジュアルです。

## 参考にする思想

次のブランドのデザイン思想を参考にしつつ、PHOSARA独自の世界観へ昇華します。
これらをそのまま模倣してはいけません。

| ブランド | 参考にする要素 |
|---|---|
| **Apple** | 余白・素材感・情報の整理・シンプルさ |
| **Notion** | 可読性・情報設計・静かな機能美 |
| **Linear** | 精密なグリッド・テキスト中心・ミニマル |
| **Stripe** | 信頼感・プロフェッショナル・明快な構成 |
| **Vercel** | 暗さと光のコントラスト・技術的な美しさ |

## 禁止事項

以下はPHOSARAのビジュアルとして禁止です。

### デザインとして禁止

- **装飾のための装飾**：意味や目的のない装飾的な要素の追加
- **情報の詰め込み**：一画面に情報を詰め込みすぎること
- **カラーの乱用**：3色以上を同時に多用すること
- **グラデーションの乱用**：目立たせるためだけのグラデーション
- **影の乱用**：浮かせるためだけに多用するドロップシャドウ
- **角丸の不統一**：角丸の大きさを要素ごとにバラバラにすること
- **フォントの乱用**：3種類以上の書体を混在させること
- **過度なアニメーション**：動きによって情報の理解を妨げること

### コピー・テキストとして禁止

- Website Copy v1.1に記載されていないコピーをAIが独自に生成すること
- ブランドの3原則（**可視化・越境・本質**）に反する表現
- PHOSARAの価値観（本質志向・一貫再現）と矛盾する表現

# 02 Design Principles（デザイン原則）

PHOSARAのすべての画面設計は、以下6つの原則に基づきます。

## 原則 01：余白（White Space）

余白はデザインの「空き」ではありません。**設計された静寂**です。

余白は次の役割を担います。

- 情報の区切りと関係性を視覚的に伝える
- 重要な要素を際立たせる
- 読み手に呼吸の余地を与え、情報を受け取りやすくする
- ブランドの「静かな高級感」を演出する

**余白の使い方**

- セクション間の余白は、要素間の余白より大きくとる
- 文字周辺の余白は、文字の読みやすさを最優先して設定する
- 余白を削って情報を増やすのではなく、情報を絞って余白を確保する
- 具体的な余白の値はDesign System v2.0で定義予定

## 原則 02：可読性（Readability）

文字が正しく読めること。これはPHOSARAの最優先事項です。

- コンテンツは**文字中心**で構成する（画像は補助）
- 本文の文字サイズ・行間・行長を適切に設定し、長文も読みやすくする
- コントラスト比はWCAG 2.1 AAレベル以上を必須とする
- 装飾フォントや細すぎる書体は使用しない
- 具体的なサイズ・フォントはDesign System v2.0で定義予定

## 原則 03：情報設計（Information Architecture）

Blueprint v1.1の方針に従い、情報設計は以下の原則で行います。

- **一画面一目的**：1つのセクションが果たす役割は1つに絞る
- **情報の順序**：Blueprint v1.1の「06 情報設計（IA）」に定義された順序を守る
  1. PHOSARAとは
  2. なぜ診断なのか
  3. 解決までの流れ
  4. 業界別ソリューション
  5. 実績・信頼
  6. 問い合わせ
- **導線の一本化**：CTAを乱立させず、各ページのゴールとなるCTAを1つに絞る
- **重要度の明確化**：見出し・本文・補足の区別をタイポグラフィで明確にする

## 原則 04：視線誘導（Eye Flow）

読み手の視線を自然に誘導し、情報を正しい順序で受け取ってもらいます。

- 日本語サイトでは縦方向のスクロールを基本とする
- 視線の流れは「大見出し → リードコピー → 本文 → CTA」を基本とする
- 横方向に要素を並べる場合は、重要度の高い要素を左または上に配置する
- 視線誘導を妨げるような装飾・アニメーションは排除する

## 原則 05：静寂（Silence）

PHOSARAのコアバリュー「Silence（静寂）」は、ビジュアルに直接反映されます。

- **要素を減らす**：画面内の要素数を常に最小化する
- **色を絞る**：使用する色の種類を最小限に保つ
- **動きを抑える**：アニメーションは存在を感じさせない程度に留める
- **声を揃える**：すべての要素がバラバラに主張せず、全体として静かに語りかける

「もう削れる要素はないか？」を常に問いかけることが、静寂の設計です。

## 原則 06：Hierarchy（情報の階層）

情報の重要度を視覚的なサイズ・太さ・余白によって明確に表現します。

- Display → H1 → H2 → H3 → 本文 → 補足の順に情報を整理する
- 同じ階層の要素は必ず同じデザインで統一する
- 階層のルールはDesign System v2.0で具体値として定義予定

# 03 Color Philosophy（カラーの思想）

> HEX値・具体的な色の指定はDesign System v2.0で定義予定です。
> 本節では「色の役割と考え方」のみを定義します。

## ブランドカラーの考え方

PHOSARAのカラーシステムは、ブランドの世界観「**光・静寂・本質・境界**」を色で表現します。

- 派手さではなく、**品位と静けさ**を最優先する
- 背景は明るく、文字はくっきりと読める
- アクセントカラーは「光の差し込み」のように、限られた場所にのみ使う
- **色自体が主役になってはいけない。情報が主役、色は裏方**

## カラーの役割分類

| 役割 | 説明 | 使用場所 |
|---|---|---|
| **Primary Color** | ブランドの中心となる色。信頼・本質を表す | ロゴ・主要見出し・Primary Button |
| **Secondary Color** | Primaryを支える補助色 | サブ見出し・補足情報 |
| **Accent Color** | 行動を促す色。光が差し込むような使い方をする | CTAボタン・重要なリンク |
| **Background Color** | サイト全体の基盤色。清潔さと余白感を演出する | ページ背景・セクション背景 |
| **Surface Color** | カード・パネルなど要素の背景色 | カード・ナビゲーション背景 |
| **Border Color** | 要素を区切る境界線の色。存在を主張しない | 区切り線・カードの枠・入力欄の枠 |
| **Text Color** | 文字の色。可読性を最優先で設定する | 見出し・本文・ラベル |
| **Muted Text Color** | 補足的なテキストの色 | 日付・タグ・補足説明 |
| **State: Success** | 正常完了を示す色 | フォーム送信完了・成功メッセージ |
| **State: Warning** | 注意を促す色 | 警告メッセージ |
| **State: Error** | エラーを示す色 | 入力エラー・エラーメッセージ |

## アクセントカラーの使用ルール

アクセントカラーは「光の差し込み」として使います。多用してはいけません。

**使って良い場所**

- Primary CTAボタン（「無料相談を予約する」など）
- 重要なリンクのホバー状態
- アクティブな状態のナビゲーション

**使ってはいけない場所**

- 装飾目的のハイライト
- 複数の要素への同時使用（乱用）
- 背景全体への適用

## 背景色の考え方

PHOSARAの背景は「光を感じる空間」でなければなりません。

- 基本は明るい背景（白または極めて明度の高い色）
- 背景色自体が主張してはいけない
- セクションの区切りに背景色を変える場合も、変化は微細に
- 具体的なカラー値はDesign System v2.0で定義予定

## 境界線（Border）の考え方

境界線は「存在するが主張しない」ことが理想です。

- 細く（1px以下が基本）
- 薄く（Border Colorは主張しない色）
- 必要な場所にのみ使い、乱用しない

## ダークモードについて

ダークモードへの対応はPhase 3以降で検討します。初期実装はライトモードのみとします。

# 04 Typography Philosophy（タイポグラフィの思想）

> 具体的なフォント名・サイズ・ウェイトの数値はDesign System v2.0で定義予定です。
> 本節では「文字組の考え方と方針」のみを定義します。

## タイポグラフィの役割

PHOSARAのWebsiteにおいて、**文字はデザインの主役**です。

画像よりも文字が価値を伝えます。文字が読みやすく、美しく組まれていることが最優先事項です。

## フォント選定の方針

PHOSARAは次の方針でフォントを選定します。

- **日本語フォント**：可読性が高く、品位があること。教科書体・丸ゴシックは使用しない。モダンな明朝体またはゴシック体を選ぶ
- **欧文フォント**：幾何学的でシンプルなサンセリフ体。スポーツ系・手書き系は使用しない
- **フォントの数**：日本語1種類・欧文1種類。合計2種類までに限定する
- **具体的なフォントファミリー名**：Design System v2.0で定義予定

## 文字の階層（Typographic Hierarchy）

情報の重要度を文字で表現します。

| レベル | 用途 | 特徴 |
|---|---|---|
| **Display** | ページの最上位見出し（Hero等） | 最大サイズ・太め・余白を大きくとる |
| **H1** | ページタイトル | 大きく・視認性最優先 |
| **H2** | セクション見出し | 明確な区切りをつくる |
| **H3** | サブ見出し | H2より小さく、本文と差をつける |
| **Body Large** | リードコピー・重要本文 | 読みやすさ優先・行間を広く |
| **Body** | 通常の本文 | PHOSARAの基本サイズ |
| **Small** | 補足・キャプション・ラベル | 控えめに、でも読める |
| **Caption** | 日付・タグ・注記 | 最小サイズ |

具体的なfont-size・font-weight・line-heightはDesign System v2.0で定義予定。

## 行間・行長のルール

- **行間（line-height）**：日本語本文は余裕のある行間を確保する。具体値はDesign System v2.0で定義予定
- **行長**：1行あたりの文字数を適切にコントロールし、長すぎる行は読みにくいため避ける。コンテナ幅で管理する
- 行長が長すぎると可読性が下がるため、コンテナ幅で適切に制御する

## 日本語・英字・数字の組み合わせ

PHOSARAのWebsiteでは日本語と英字・数字が混在します。

- 日本語と英字の間には適切なスペース感を確保する
- 英字・数字は欧文フォントを使用し、日本語フォントでのレンダリングを避ける
- 見出しに英字（PHOSARA・Business Audit等）が入る場合、欧文フォントが適用されるようにマークアップする

## 見出しの組み方

- 見出しは短く、核心をついた言葉を選ぶ（Website Copy v1.1から引用）
- 見出しを折り返す場合は、意味の切れ目で改行する
- 見出しに句読点（。、）は原則使用しない

## 本文の組み方

- 本文は読みやすさを最優先する
- 漢字・ひらがな・カタカナのバランスに注意し、堅すぎず・柔らかすぎない文体を保つ
- Website Copy v1.1に記載されたコピーをそのまま使用し、AIが独自に書き換えてはいけない

## 禁止事項

- 3種類以上のフォントを混在させること
- 本文に装飾フォント（Script体・手書き体等）を使用すること
- 読みにくいほど細いウェイト（Thin・Hairline等）を本文に使用すること
- 過剰なカーニング調整による不自然な文字間隔
- Website Copy v1.1にないコピーをAIが生成・変更すること

# 05 Grid Philosophy（グリッドの思想）

## グリッドの役割

グリッドは「見えない秩序」です。ユーザーには見えませんが、すべての要素がグリッドに沿って配置されることで、画面全体に秩序と安定感が生まれます。

PHOSARAのグリッドは、**Blueprint v1.1で定義された方針**に従います。

## 12カラムグリッド

- サイト全体は**12カラムのグリッド**を基本とする
- コンテンツはカラム数を組み合わせて配置する（例：6+6、8+4、12など）
- 常に全てのカラムを使う必要はない。余白を残すことを恐れない
- カラム数・ガター幅の具体値はDesign System v2.0で定義予定

## 8pxグリッド

- すべての余白・サイズは**8の倍数（8px、16px、24px、32px、48px、64px…）**で設定する
- 例外的に4px（8の半分）を使用することがあるが、8の倍数を基本とする
- 8pxグリッドは画面全体の秩序と一貫性を保つための基盤

## コンテナ（Container）

コンテナはコンテンツを画面中央に配置し、左右の余白を確保します。

- コンテナ最大幅・サイドマージンの具体値はDesign System v2.0で定義予定
- モバイル・タブレット・デスクトップで適切にコンテナ幅が変化する（モバイルファースト）
- コンテンツは常にコンテナ内に収める（FullWidthの背景色・画像は除く）

## ブレークポイント（Breakpoints）

Blueprint v1.1の「20 UI/UX設計方針」に従い、**モバイルファースト**で設計します。

| 名称 | 対象デバイス | 具体的な幅 |
|---|---|---|
| Mobile | スマートフォン | Design System v2.0で定義予定 |
| Tablet | タブレット | Design System v2.0で定義予定 |
| Desktop | PC・大画面 | Design System v2.0で定義予定 |

## セクション間の余白（Section Spacing）

- セクションとセクションの間の余白は、要素間の余白よりも大きくとる
- セクション余白の具体値はDesign System v2.0で定義予定
- 余白が大きいほど「静かな高級感」が増す。削りすぎないこと

# 06 Shape Language（形の言語）

形の使い方にもPHOSARAの世界観を反映させます。

## 角丸（Border Radius）

PHOSARAは「本質的・引き算」のブランドです。角丸も最小限に抑えます。

- **基本方針**：シャープな印象を基本とし、角丸は控えめに使用する
- **カード・パネル**：わずかな角丸（小さいRadius）を使用。丸くなりすぎない
- **ボタン**：完全な円形（Pill）は避ける。適度な角丸または直角に近い形
- **入力フォーム**：カードと統一したRadius
- **具体的な数値**：Design System v2.0で定義予定

角丸を大きくすることで「親しみやすさ」は増しますが、PHOSARAが目指す「静かな高級感」とは異なります。角丸は必要最小限に留めます。

## 線（Line & Border）

- **ボーダー（境界線）**：細く、存在を主張しないこと。1px以下を基本とする
- **区切り線**：セクションの区切りに薄い水平線を使用することがある。装飾ではなく区切りのための線
- **線の色**：Border Colorを使用し、濃くしすぎない
- **線の太さの統一**：ページ内で複数の太さの線を混在させない

## カード（Card）

カードはコンテンツをグルーピングする器です。

- シンプルな構造：背景色 + 適度な内部余白 + 小さな角丸
- 影（ドロップシャドウ）は原則使用しない、または極めて薄く抑える
- カードはコンテンツを引き立てる脇役であり、カード自体が目立ってはいけない
- ホバー時は控えめな変化（色の変化・軽微な移動）のみ

## ボタン（Button）

ボタンはユーザーへの「行動の促し」です。目的を果たす最小の形を選びます。

- **Primary Button（主要行動）**：Accent Colorを使用。サイト内で最も目立つ要素。「無料相談を予約する」等のCTAに使用
- **Secondary Button（補助行動）**：Background + Borderを使用。控えめな印象
- **Text Button（リンク的な行動）**：装飾なし、テキストのみ
- ボタンは乱立させない。Blueprint v1.1の「20 UI/UX設計方針」に従い、CTAは各ページ1つを基本とする

## 境界（Boundary）

PHOSARAのコアバリュー「Boundary（境界）」は、既存の枠の先へ行くことを意味します。

デザイン上の「境界」は、要素を区切る線・余白・色の差によって表現されます。境界は主張しすぎず、しかし確かに存在する——それがPHOSARAの「境界」です。

# 07 Motion Philosophy（モーションの思想）

PHOSARAのモーション（動き）は**「存在を感じさせない」**ことを目標とします。

## モーションの定義

本書における「モーション」は、Webアニメーションに限りません。

PHOSARAが今後手がける**動画制作・モーショングラフィック・プレゼンテーション動画**など、
あらゆる「動き」に共通する思想として定義します。

媒体が変わっても、PHOSARAのモーションは同じ思想に従います。

## 設計思想（Motion Design Principles）

PHOSARAのモーションはすべて、次の3つの原則に従います。

### 原則1：情報を補助する（Motion Assists Information）

動きは、情報の理解を助けるために存在します。

「かっこいいから」「注目を集めたいから」という理由だけの動きは使いません。
モーションは常に「これはユーザーの理解を助けているか？」という問いに答えられるものだけを選びます。

動きがなくても情報が伝わるなら、動きは不要です。

### 原則2：ユーザーを邪魔しない（Motion Doesn't Interrupt）

動きは、ユーザーの操作・読書・思考を妨げてはいけません。

モーションが目立ちすぎると、情報ではなく動き自体が主役になってしまいます。
PHOSARAのモーションは「存在しているが気にならない」レベルに抑えます。

動画においても同様です。過剰なトランジション・効果音・テロップの乱用は、
伝えたい情報の理解を妨げるため使用しません。

### 原則3：意味のある動きだけを使う（Only Meaningful Motion）

使用するすべてのモーションには意味があります。

- フェードイン → 「情報が現れる」ことを自然に伝える
- ホバー → 「操作できる」ことを示す
- ローディング → 「処理中」であることを示す
- 動画のカットイン → 「次の情報へ移る」ことを示す

意味を持たない装飾的なモーションは、PHOSARAのビジュアルには存在しません。

## Webアニメーションの基本方針

以下はWebサイト実装時のアニメーション方針です。

- **動きは最小限**：アニメーションは情報理解を補助するために存在する。演出のためではない
- **PHOSARAらしい動き**：静かで、品位があり、速すぎず遅すぎない
- **操作性を妨げない**：アニメーションがあることで、操作が遅くなったり情報が理解しにくくなってはいけない
- **`prefers-reduced-motion`対応**：ユーザーが動きを減らす設定をしている場合は、アニメーションを無効にする

## 速さ（Duration）

- すべてのアニメーションは「速い」か「遅すぎない」かのバランスを保つ
- 具体的なミリ秒値はDesign System v2.0で定義予定

## イージング（Easing）

- **基本**：ease-out（始まりが速く、終わりが緩やか）を標準とする
- 入ってくる動き（フェードイン・スライドイン）はease-outを使用
- 出ていく動き（フェードアウト）はease-inを使用
- イージングの具体値（cubic-bezier）はDesign System v2.0で定義予定

## フェード（Fade）

フェードはPHOSARAの標準アニメーションです。

- **フェードイン**：スクロールで要素が画面内に入った際に、軽く浮き上がりながら表示される
- **フェードアウト**：ページ離脱時など、必要な場合のみ使用する
- 過度なスライド・バウンス・回転は使用しない

## Hover（ホバー）

PCでのマウスオーバー時の変化。変化は微細で上品に。

- **テキストリンク**：色の変化のみ
- **ボタン**：わずかな背景色の変化・透明度の変化
- **カード**：極めて微細な移動または背景色の変化のみ
- **ナビゲーション**：アクティブ色への変化
- 派手なエフェクト・過度な拡大・影の急変は使用しない

## スクロール（Scroll）

スクロールに連動するアニメーションは最小限に留めます。

- **スクロールフェードイン**：セクションが画面に入った際にフェードインする（推奨）
- **パララックス効果**：原則使用しない（過度な演出につながるため）
- スクロールが快適で滑らかであることを最優先する

## ローディング（Loading）

- ページの読み込みが完了するまでの表示は最小限にする
- 回転するアイコン（スピナー）は使用しない。必要な場合はシンプルなプログレスバーまたはスケルトン表示
- ローディング自体がブランドを損なわないよう、PHOSARAの世界観に合わせて設計する

# 08 Photography（写真の世界観）

## 写真の役割

PHOSARAのWebsiteにおいて、写真は**情報を補助する脇役**です。

写真そのものが主役になってはいけません。文字・情報が伝わることを優先し、写真はその理解を助けるために存在します。

## 世界観

PHOSARAの写真に共通するトーンは「**自然光・余白・静けさ**」です。

- 自然光を活かした、明るく清潔感のある写真
- 余白（空間）があり、息苦しくない構図
- 静かで品位があり、過度な演出がない
- PHOSARAのブランドカラーと調和する色味（Design System v2.0のカラー定義後に再確認）

## 人物写真

- 自然な表情・自然なポージング。作り物感のない写真
- 過度なレタッチ（肌の均一化・背景の合成）は避ける
- 特定の業界のユーザーが「自分ごと」として感じられる写真
- 笑顔を強制しない。真剣に・誠実に向き合う人物像

## 建築・空間写真

- 直線・秩序・清潔感のある構図
- 施工品質・素材感が伝わるディテールショット
- 建設業・リフォーム業の実績写真は「変化が伝わるもの」を優先

## 自然光

- 蛍光灯・人工的な照明の印象が強い写真は使用しない
- 自然光が差し込む・柔らかい光の写真を優先する
- 光の印象がPHOSARAのブランドエッセンス「PHOS（光）」と一致することを意識する

## 色味（Color Tone）

- 彩度を適度に抑えた、落ち着いたトーン
- 過剰にカラフルな写真は使用しない
- 暖色すぎず・寒色すぎない、ニュートラルな色味を基本とする
- ブランドカラーと調和していること

## 禁止写真

以下の写真はPHOSARAには使用しない。

- **過剰加工・合成写真**：明らかに合成・過度なレタッチをした写真
- **ストックフォトらしい写真**：ポーズが不自然で、あからさまにストックフォトとわかるもの
- **暗すぎる・重すぎる写真**：PHOSARAの「光・静寂」の世界観と合わない
- **騒がしい構図の写真**：情報が多すぎて落ち着かない写真
- **低解像度の写真**：粗い・ぼやけた写真
- **競合他社の事例写真**：他社実績と混同される可能性のある写真

# 09 Iconography（アイコンの使い方）

## アイコンの役割

アイコンは「補助的な視覚要素」です。テキストが理解を助けられない場面でのみ使用します。アイコンだけで情報を伝えることは原則しません。

## スタイルの統一

- **スタイル**：Outline（線画）スタイルに統一する。Filled（塗り）は使用しない
  - 理由：Outline styleは「引き算・本質」のPHOSARAの世界観に合致するため
- **線幅（Stroke Width）**：全アイコンで統一する。サイズが変わっても線幅の視覚的な印象は統一する
- **角の形状（Stroke Cap / Join）**：全アイコンで統一する（角丸または直角、どちらかに統一）
- **具体的な線幅の値**：Design System v2.0で定義予定

## サイズ

- アイコンは8pxグリッドに沿ったサイズで使用する（例：16px、24px、32px）
- 文字と並ぶ場合は、文字の高さに合わせてサイズを調整する
- 極端に大きなアイコン（装飾的な使用）は避ける

## 使用方針

- テキストを補助する場面でのみ使用する（テキストと必ずセットで使う）
- ナビゲーション・機能の説明・リストの先頭など、限られた場所で使用する
- 装飾目的での使用は禁止

## アイコンの選定

- PHOSARAの世界観（光・静寂・本質・境界）と一致するシンプルなデザインのアイコンを選ぶ
- 統一されたアイコンセット（ライブラリ）を1種類選んで使用する
- 使用するアイコンセットはDesign System v2.0で定義予定

# 10 Illustration（イラストレーション）

## 基本方針

PHOSARAにおいて、イラストは**原則使用しない**。

イラストはブランドのトーンをコントロールすることが難しく、「本質的・引き算」のPHOSARAの世界観と合わないケースが多いです。

## 例外的な使用

以下の限られた場面では、イラストの使用を検討することができます。

- エラーページ（404ページ等）でのシンプルなグラフィック
- フロー図・プロセス図における補助的な図解（情報を伝えるための図解に限る）

## イラストを使用する場合の基準

やむを得ずイラストを使用する場合は、以下の基準をすべて満たすこと。

- PHOSARAのカラーシステムに準拠した色使い
- 線画またはフラットなスタイルに限定する（写実的・3Dイラストは禁止）
- ブランドの「本質・静寂」の世界観と一致すること
- **オーナーの明示的な承認を得てから使用すること**

# 11 Accessibility（アクセシビリティ）

## PHOSARAとアクセシビリティ

アクセシビリティは「特定のユーザーへの配慮」ではなく、**すべてのユーザーにとっての使いやすさ**です。

PHOSARAが追求する「可読性・静寂・秩序」は、アクセシビリティの本質と一致します。正しく設計されたPHOSARAのデザインは、必然的にアクセシビリティが高くなります。

**準拠基準：WCAG 2.1 AA レベル**以上を必須とします。

## コントラスト

- **本文テキスト**：背景色に対して4.5:1以上のコントラスト比を確保する
- **大きなテキスト（見出し等）**：3:1以上のコントラスト比を確保する
- **UIコンポーネント（ボタン枠・入力欄等）**：3:1以上のコントラスト比を確保する
- 具体的な色の組み合わせはDesign System v2.0のカラー定義後に検証する

## 可読性

- フォントサイズは本文を最低16px以上に設定する（具体値はDesign System v2.0で定義予定）
- テキストのみで情報が理解できるように設計する（色・アイコンのみで情報を伝えない）
- 行間・行長は「02 Design Principles」の可読性原則に従う

## 操作性

- **キーボード操作**：マウスなしでタブキーのみで全ての操作が可能であること
- **フォーカス表示**：キーボードフォーカス時に視覚的なフォーカスリングを表示する。非表示にしない
- **クリック・タップ領域**：ボタン・リンクのクリック/タップ可能な領域は44×44px以上を確保する
- **フォームのラベル**：すべての入力欄にラベルを明示する（placeholderのみに頼らない）

## 代替テキスト

- すべての意味のある画像にalt属性を設定する
- 装飾目的のみの画像はalt=""（空）にする
- アイコンに意味がある場合は、aria-labelで説明を付与する

## アニメーションとアクセシビリティ

- `prefers-reduced-motion`メディアクエリに対応し、ユーザーが動きを減らす設定をしている場合はアニメーションを無効にする
- アニメーションが情報の理解に必須な場合は代替手段を提供する
