# AUDIT_REPORT_TEMPLATE.md — 監査報告書テンプレート

**体裁:** 黒背景・白文字・赤は要所のみ(PXD準拠)。1ページ1メッセージ。全所見にエビデンス源表記(観/対/資/計)。
**分量目安:** 18-24ページ。厚さではなく密度で語る。

---

## P1 表紙
`PHOSARA — BUSINESS AUDIT REPORT`
{クライアント名} 御中 / 実施期間 / 報告日 / 担当

## P2 総括(Audit Summary)— 全報告書で最も重要な1枚
- **総括所見(3行以内・人間が自分の言葉で書く)**
- **最優先課題(一言):** ________
- **推奨する次の一手(一言):** ________
- 監査の目的と対象範囲(2行)

## P3 診断の方法(1枚)
11の窓(モジュール)× 6つの構造(領域)/ 三つの証拠源 / スコアは優劣でなく優先度——の3点を簡潔に。

## P4 レーダーA: 6領域(戦略の一枚)
チャート+各領域スコア・信号の一覧表+一行所見

## P5 レーダーB: 11モジュール(実務の一枚)
チャート+信号一覧(🔴🟡🟢)

## P6 強みの確認(価値の生成点)— 必ず漏出点より先に置く
🟢領域・モジュールから2-3点。**ヒアリングでの本人の言葉を引用**して裏付ける。
「この強みは守り、以後のすべての改善の軸にする」と明記。

## P7-P17 モジュール別所見(1モジュール1ページ、🔴🟡中心に厚く、🟢は簡潔に)
各ページ構成:
- モジュール名+信号+スコア
- **発見(2-4点):** 観察事実→意味(なぜ事業価値が漏れるのか)。スクリーンショット・計測値を添付
- **エビデンス源表記**
- (該当時)クイックウィン候補のマーク ⚡

## P18 症状と構造(分析の核心・1枚)
症状の連鎖図: 「{症状A}・{症状B}の根に{構造的要因}がある」を1枚の図で。
※この1枚が「チェックリスト屋」と「診断」の分水嶺。

## P19 優先課題(Priority Issues)
| 順位 | 課題 | 関連領域 | 事業価値への影響 | 根拠 |
|---|---|---|---|---|
| **1(最優先)** | | | | |
| 2 | | | | |
| 3 | | | | |
最優先課題を選んだ理由(構造的要因である旨)を3行で。

## P20 戦略的方向性(Strategic Direction)
- 解決すべきこと(何を)
- 可視化すべき価値(どの価値を)
- **方向性の要約(一行・太く)**
※解決策・媒体・制作物はここでは確定しない旨を注記(次工程の設計対象)。

## P21 改善ロードマップ(要約)
30日クイックウィン⚡ / 60日土台 / 90日構造改善 / 1年戦略 の4段表(詳細は別紙IMPROVEMENT_ROADMAP)。
クイックウィンには「御社だけで実施可能。手順ガイドを添付します」と明記(贈り物)。

## P22 次の一手(最終ページ・静かに一度だけ)
「本監査は、解くべき課題と方向を定めました。この方向の**設計**——どう解くか——をご一緒する場合の進め方をご案内できます。ご関心があればお声がけください。」
+ 次段の概要(名称・期間・進め方のみ。価格は口頭または別紙)
+ 連絡先

## 検証(提出前・AUDIT_VERIFICATION.md ゲートDに統合。以下は要点)
- [ ] サマリー3行は人間の言葉か(AIドラフトのままになっていないか)
- [ ] 強みページが漏出点より先にあるか
- [ ] 全所見にエビデンス源/優先課題は1点に絞れているか/方向止まりか
- [ ] クイックウィン⚡が最低2つあるか(それ自体で元が取れる監査の条件)
- [ ] 次の一手は最終ページに一度だけか(途中で売っていないか)
- [ ] 信号・スコア・レーダー・本文の数値が完全一致しているか
